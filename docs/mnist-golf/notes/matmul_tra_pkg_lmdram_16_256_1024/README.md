## 判明した下限（アセンブラのハザード検査で確認）

- スコア = ソース 1 行 = PE 命令語 1 語 + MV 語。末尾は
  `l2bmd` 32 語 + `nop` 1 語 + `mvrffadd` + `mvp`×4 の 38 語が必須。
- `l2bmd` は 1 命令で L2BM に 256 長語しか書けないので 8192/256 = 32 命令が下限。
- `l2bmd` の直後に L2BM を読む MV を置くと DataRace になるので `nop` が要る
  （2 歩空けは PortConflict で拒否、3 歩必要）。
- `mvrffadd/n8192 $lc0 $d0` で PDM を介さず直接 DRAM へ書くと、DRAM の
  16 長語交互配置が必要になるが、`l2bmd` の 64 長語ブロックは
  1 サイクル分（= 1 行）のデータしか含められないため両立しない。
- `mvr`/`mvp` を 4 語にする道はこの配置制約で不可能。

## 60 行に必要な条件

`coll(0)` を 19 歩に置くと `l2bmd` を 22 歩から始められ 60 行になる。
そのためには行列レジスタ書き込み（mwrite グループ、1 歩 1 命令）を
18 個ステップ 0..17 に詰める必要がある。

- 必要 mwrite: Bᵀ 転置 8 + A 転置 2 + 行列ロード 8 = 18。
- T レジスタは `ipassa`→`iadd` の 2 命令が必要で、書き込み後 1 歩空ける
  必要があるため A 転置の書き込みは 3 歩目が最速。よって 2 歩目は
  mwrite に使えない（A を 2 歩目に置くと DataRace）。
- さらに `gmread`（転置読み出し）は列指定で 8 行すべてを集めるので、
  A の 2 ウィンドウは同一フェースの行 0-3 / 4-7 に置く必要があり、
  2 歩目に他チャンクを置くと 3/4 歩目の A 書き込みで壊れる。

→ 2 歩目が埋まらず 18 mwrite に 19 歩必要 → 先頭は 23 歩 → 61 行が下限。
