# VSM を読みやすいコードへ変換するための中間表現

対象は `problems/` の VSM 解答。まず機械の動作を明示し、その表現から計算の意図を復元する。
既存 VSM からの lifting と往復変換は設計段階であり、まだ実装していない。
高級言語からの入口として、[mncompile](../mncompile/README.md) に、LLVM を通す多項式・配列コンパイラがある。
original Challenge 全25問の高級言語ソースと生成結果を用意し、入力値に依存しない命令選択規則として実装している。
ただし、既存VSMを自動でこの高級言語へ持ち上げる処理とは別の入口である。

最終目標は、高級言語で計算・入力範囲・許容誤差を指定すると、その範囲で VSM の行数を最小化すること。
LLVM の一般最適化に、MN-Core の数値表現、命令選択、配置、同時発行、ハザードを考慮する探索を重ねる。
高級言語からのコンパイルと既存 VSM の lifting を、共通の意味IR・機械IRで接続する。

## 変換の段階

```text
VSM
  ↓ 既存の vsm::parse
構文木：演算、精度、オペランド、4サイクル分のアドレス
  ↓ 型・読み書き・同時発行・フォワーディングを明示
機械の意味を保持する IR
  ↓ 依存関係とメモリエイリアスを確認しながら変数化
データフロー IR
  ↓ データ配置の復元、繰り返しの整理、演算パターンの認識
配列演算を使う高級言語
```

変換元との対応を各段階で残す。読みやすさのために省略する情報と、同値性に必要な情報を区別する。

## 最初の IR が保持するもの

- 元の行番号と命令。未対応の命令は未対応と明示する。
- PE 命令のステップと、その中で同時発行する演算の組。
- 演算の種類、整数の符号・幅、浮動小数点の形式、丸め、精度拡張、フラッシュ。
- メモリ空間とアクセス幅。単語アドレスと値の型は別々に表す。
- 各サイクルのアドレス、ベースアドレスレジスタ、T による間接参照、PE による補正。
- 読み書きのマスクと、書かなかった領域の保持。
- フォワーディングの読み元・更新先と、その値を参照するタイミング。
- PE / MAB / L1B / L2B / group の範囲、転送・縮約の方向。
- nop、wait、MV のタグと順序。削除や並べ替えは別の検証を必要とする。

`;` で結ばれた命令を、通常の逐次代入に置き換えてはいけない。
既存シミュレータの評価順序と、SDM・公式エミュレータで確認できる動作を基準にする。
ステップ単位の単純なメモリスナップショットで十分かどうかも、各データ経路について確認する。

## 読みやすい表記の例

Welcome の解答:

```text
iinc $lm0v $ln0v
iinc $lm8v $ln8v
```

意図を表す上位の表記は次のようにできる。
これは Python の実装ではなく、型付き配列演算の擬似コードである。

```python
for pe in all_pes:
    output_i32[pe, 0:16] = wrapping_add_i32(input_i32[pe, 0:16], 1)
```

この表記まで持ち上げる前に、下位 IR で次を確認する。

- 最初の命令は LM0 の単語アドレス `[0, 2, 4, 6]` から各2単語を読む。
- 次の命令は `[8, 10, 12, 14]` から各2単語を読む。
- 各単語を独立した32ビット整数として加算する。64ビット加算には変えない。
- 出力先は LM1 の対応する単語。PE ごとの入力・出力配置を保持する。

`mauf` や `aluf` は、その生存期間を確認した上で `t0`, `t1` のような変数にする。
LM、GRF、ブロックメモリは読み書きを明示し、間接参照やマスクのある領域を不用意に変数へ置換しない。

## 等価性の確認

「IR に情報が残っている」「既存シミュレータで同じ結果になる」「公式エミュレータと一致する」は別々の確認である。
公開テストケースの一致は、その入力についての確認であり、全入力の同値性の証明ではない。

1. 変更を加えない IR から VSM へ戻し、元の演算・同時発行・順序・オペランドが保たれることを確認する。
2. IR の実行結果を、既存シミュレータと公式エミュレータの両方に照合する。
3. データフロー化や配列演算への変換ごとに、変換条件と対応する元命令を記録する。
4. 整数の桁あふれ、マスク、間接参照、符号付きゼロ、丸め境界などを必要な演算ごとに確認する。

通常の NumPy の浮動小数点演算が、そのまま MN-Core の演算と一致するとは仮定しない。
Convert Endian の公開解答は浮動小数点の積和命令をビット変換に利用しているため、
数式として簡約する前にビット列としての意味を保持する必要がある。

## 最初の実装範囲

既存コードを再利用する。

- `viz/core/src/vsm.rs`: 型付き構文木とパーサ。
- `viz/core/src/machine.rs`: PE の実行、オペランドの評価、フォワーディング。
- `viz/core/src/run.rs`: プログラムの実行とメモリ初期化・読み出し。
- `viz/core/src/float.rs`: MN-Core の数値表現。
- `viz/core/src/api.rs`: 行と演算、データ移動の対応付け。

最初は Welcome、A + B、Convert Endian の3問を対象にする。
単純な整数演算、フォワーディング、同時発行とビット表現を順に扱える。
この3問で、IR の保存・再読み込み、読みやすい表示、VSM への復元、実行結果の比較を揃える。
配列演算の認識や別言語へのコード生成は、その足場の上に追加する。
