# 縮小トポロジ

Rust シミュレータ（`viz/core`）は、実チップより小さい構成でも動く。
L2B・L1B・MAB の数と各メモリの容量を実行時に指定する。
FPGA に縮小構成の MN-Core 2 を作るとき（nano20k の共通契約 §3）の正解を作るためのもの。

- 実装: `viz/core/src/topology.rs`（`Topology`）
- 使い方: `Sim::with_topology(topo)`、`sim_run --topology ...`、`difftest_file --topology ...`
- 既定は実チップ（`Topology::FULL`）。既定構成の動作は、トポロジ対応の前と変わらない（下の「既定構成」）。

## パラメータ

| キー | 意味 | 単位 | 範囲（最大が実チップ） | 契約 §3 の名前 |
| --- | --- | --- | --- | --- |
| `l2b` | L2B の数。n0c0、n0c1、n1c0、... の順に数える | 個 | 1〜8 | `N_L2B` |
| `l1b` | L2B あたりの L1B の数 | 個 | 1〜8 | `N_L1B` |
| `mab` | L1B あたりの MAB の数 | 個 | 1〜16 | `N_MAB` |
| `pe` | MAB あたりの PE の数。常に 4 で、4 以外は指定できない | 個 | 4 | `N_PE` |
| `lm` | PE ごとの LM0 / LM1 の容量 | 長語 | 1〜2048 | `LM_DEPTH` |
| `grf` | PE ごとの GRF0 / GRF1 の容量 | 長語 | 1〜256 | `GRF_DEPTH` |
| `l1bm` | L1B ごとの L1BM の容量 | 長語 | 1〜8192 | `L1BM_DEPTH` |
| `l2bm` | L2B ごとの L2BM の容量 | 長語 | 1〜32768 | `L2BM_DEPTH` |
| `pdm` | グループごとの PDM の容量 | 長語 | 1〜512Ki | （なし） |
| `dram` | グループごとの DRAM の容量 | 長語 | 1〜512Mi | （なし） |

仕様文字列は `キー=値` をコンマでつなぐ。省略したキーは実チップの値になる。

```
l2b=1,l1b=1,mab=1,lm=256,grf=256,l1bm=1024,l2bm=4096     # 契約 §3 の初期構成
l2b=1,l1b=1,mab=16,lm=256,grf=256,l1bm=1024,l2bm=4096    # P3（16 MAB）
full                                                    # 実チップ（空文字列も同じ）
```

値は 10 進か `0x` で始まる 16 進で、`Ki`（1024 倍）と `Mi`（1048576 倍）を付けられる。
未知のキー、重複したキー、範囲外の値はエラーになる。

## ユニットの番号

縮小構成は、実チップのユニットを n0c0b0m0p0 から順に残したものとする（契約 §3）。

- L2B の番号 i（0〜7）は、グループ i / 2 の L2B i % 2（`n{i/2}c{i%2}`）。`l2b=3` なら n0c0、n0c1、n1c0 がある。
- 各 L2B は L1B `b0`〜、各 L1B は MAB `m0`〜を持つ。
- `$l2bid`、`$l1bid`、`$mabid`、`$peid`、`$subpeid` は実チップでの値を返す。
- `d set` / `d get` の位置指定とダンプの位置の表記も実チップの座標を使う。
- L2B を 1 つ以上持つグループだけが存在する（`l2b=1` ならグループ 0 だけ）。PDM、DRAM、DAR はグループごとにあるので、存在するグループにだけある。

内部では、存在するユニットを詰めて番号を振る（`Machine::pes`、`Blocks::l1bm` など）。
番号とチップ座標の変換は `Topology::pe_id`、`pe_index`、`l1b_coords` で行う。

## 存在しないユニット

縮小構成の命令は、実チップと同じ命令語を、存在するユニットだけで実行する。
ユニットをまたぐ転送の相手が存在しないときは、次のように扱う。

1. **存在しないユニットへの転送は捨てる。** 読み出しも行わない。
2. **存在しないユニットから受け取るデータはゼロとする。** 結合（gather）と縮約の入力が対象。
3. L2BM 縮約（`l2bmr`）では、L1B 集合の**外**にある L1B は単位元を送る（実チップと同じ）。
   集合の**中**にあるが存在しない L1B は、2. によりゼロを送る。

ゼロは「その位置の値が 0」という意味で、縮約の単位元ではない。
たとえば最大値の縮約では、存在する入力がすべて負なら結果は +0 になる。

| 命令 | 存在しないユニットが送り先のとき | 存在しないユニットが送り元のとき |
| --- | --- | --- |
| L1BM → PE（`l1bmp`、`l1bmm`、`l1bmm4`、`l1bmd`） | その MAB の PE には何もしない | （L1BM は常に存在する） |
| PE → L1BM（`l1bmm@`、`l1bmm4@`、`l1bmd`、`l1bmr`、`l1bmr4`） | （L1BM は常に存在する） | その MAB の PE の値をゼロとする |
| L2BM → L1BM（`l2bmb`、`l2bmb2`、`l2bmd`） | その L1B には書かない | （L2BM は常に存在する） |
| L1BM → L2BM（`l2bm@`、`l2bmd`、`l2bmr`、`l2bmr2`） | （L2BM は常に存在する） | その L1B の L1BM をゼロとする |
| L1BM 間（`l2bmi`） | その L1B には書かない | 送り元の L1BM をゼロとする |
| `l2bmdars` | 存在しないグループの DAR バッファには書かない | 存在しない L2B の L2BM をゼロとする |
| MV 命令 | 存在しない L2B、存在しないグループの PDM / DRAM には書かない | それらの L2BM / PDM / DRAM をゼロとする |
| `d set` / `r` | 何もしない | — |
| `d get` | 何も出力しない | — |

MAB 内の PE どうしの演算（`msl` / `msr`、行列レジスタ、`bfn`、`dvfma` の `u` / `d`）は、MAB に 4 PE がそろっているので実チップと同じになる。

## 容量の外へのアクセス

縮小した容量の外にアクセスしたら、**`E_RANGE` で停止する**（契約 §3）。黙って折り返さない。

- アドレスは、まず実チップの大きさで折り返す（実チップと同じ計算）。その結果が縮小した容量以上ならエラーになる。
  - LM0 / LM1 / GRF0 / GRF1 は語アドレスで、アクセスする全部の語（1、2、4 語）が容量に収まる必要がある。
  - L1BM / L2BM / PDM / DRAM は長語アドレス。
- PE の命令のオペランドは、ソースも書き込み先も、すべての PE とサイクルについて検査する。
  **書き込みマスクで止まる書き込みも検査する。**ベースアドレスレジスタと T 間接によるアドレスも含む。
- 存在するユニットに対するアクセスだけを検査する。存在しないユニットへの転送は行わないので検査しない。
- `d set`、`d get`、`r` の行も検査する。
- 容量を縮小していないメモリは検査しない。実チップと同じく折り返すだけになる。

エラーは `ExecError::Range` で、メッセージは次の形になる。

```
E_RANGE: LM1 n0c0b0m0p0 word address 512 (2 words) is outside the capacity of 512 words
E_RANGE: L1BM n0c0b0 long word address 1024 is outside the capacity of 1024 long words
```

`Sim::run` が返す `RunError` の `word` は、止まった文の最初の命令語の番号（0 始まり。それより前の `j` / `m` 語の数で、`nop/n` は n 語、`d` / `r` の行は 0 語）で、`RunError::is_range()` で E_RANGE かどうかがわかる。
`sim_run` は終了コード 3 を返し、行番号と命令語の番号を表示する。

LM / GRF を縮小した構成では、PE の命令を実行する前に、全 PE のオペランドを PE の番号順に検査する。
PE は並列に実行されるが、報告する PE とアドレスはこの順番で決まる。
このため、同じステップに未対応の命令などの別のエラーがあっても、PE メモリの `E_RANGE` を先に報告する
（issue 条件の違反、つまりアセンブラが拒否する行はさらに前に報告する）。
同じステップ内の先の式が T を書き換え、後の式がそれを T 間接の書き込みアドレスに使う場合だけは、実行中の検査で見つかる（このときは報告する PE が並列実行の順番に依存しうる）。
L1BM / L2BM / PDM / DRAM の検査は実行中に順番に行うので、報告は決定的になる。

## 縮小構成と全構成が一致する条件

データの移動が、トポロジに完全にそろっているユニットの中で閉じる命令列なら、
**縮小構成の結果 = 全構成の結果を縮小構成の範囲で切り出したもの** になる（容量の外にアクセスしない限り）。

| 命令列が使うもの | 一致する構成 |
| --- | --- |
| PE と MAB の中だけ（L1BM、L2BM、MV を使わない） | すべての構成 |
| L1BM 命令まで | `mab=16` |
| L2BM 命令まで | `l1b=8,mab=16` |
| MV 命令 | 一般には一致しない |

`Topology::contains` と `Topology::restrict` は、全構成のダンプから縮小構成の範囲の値を切り出す。
`viz/core/tests/topology.rs` が、手書きの命令列と `problems/` の全問題について、この一致を確かめる。

```sh
cd viz/core
cargo test --release --test topology                  # 手書きの命令列、意味の確認、代表的な問題
cargo test --release --test topology -- --ignored --nocapture   # 全問題 × 7 構成（数分）
```

後者は `scripts/check-conformance.sh` にも含まれる。手書きの命令列は、公式エミュレータがあれば、その全構成の結果を切り出したものとも比べる。

## コマンド

```sh
# d get の値を表示する（1 行 1 長語、キー順）
cargo run --release --bin sim_run -- --topology l2b=1,l1b=1,mab=16,lm=256 prog.vsm

# 全構成でも実行し、範囲内の値が一致するかを調べる（違えば終了コード 4）
cargo run --release --bin sim_run -- --topology l2b=1,l1b=1,mab=16 --compare-full prog.vsm

# 公式エミュレータ（全構成）の値を範囲で切り出して、縮小構成の Rust シミュレータと比べる
cargo run --release --bin difftest_file -- --topology l2b=1,l1b=1,mab=16 prog.vsm
```

`sim_run` の出力は `<メモリ> <位置> <アドレス> <値>` で、メモリの名前とアドレスは `Sim::dump` と同じ
（`LM0 LM1 GREG0 GREG1 TREG OMR L1BM L2BM DRAM PIU`。LM / GRF は長語の先頭の語アドレス、L1BM / L2BM / DRAM / PIU は長語アドレス、
TREG は 2 × サイクル + 長語の番号、OMR はエントリ × 4 + サイクル）。値は小文字の 16 桁の 16 進数。
`PIU` は PDM の値で、公式エミュレータの `d get $p`（DRAM を表示する）とは比べられない。

## 既定構成

既定構成（`Topology::FULL`）では、存在しないユニットも、縮小した容量もない。
上の規則はどれも働かず、命令の実行順序、アドレスの計算、ダンプの内容は従来と同じになる。
不正なユニット番号（`l1bmm@16` など、アセンブラが受け付けないもの）の扱いも変えていない。

GPU バックエンド（`gpu.rs`）は実チップだけを扱う。
