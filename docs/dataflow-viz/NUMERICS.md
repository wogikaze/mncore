# MN-Core 2 数値演算の実測メモ

`viz/core` の数値シミュレータが公式エミュレータ（`gpfn3_package_main`）とビット単位で一致するように、仕様（SDM）に書かれていない挙動を実験で確かめた記録である。

一次資料は公式の開発者マニュアル（SDM）とする。
README のリンク先の PDF を `judge/sdm/` に置いている（git 管理外）。
数値演算の定義は SDM の4章「出力の正規化」「RRN」「ベクトル積和演算」「ブロックフロート化」「行列ベクトル積和演算」にある。

## 確認の方法

`viz/core/src/bin/difftest_mau.rs` で、ランダムな入力を `d set` で 64 PE に書き込み、命令を実行して `d get` で結果を回収し、自前の実装と比べる。
入力は、ゼロ、無限大、指数の端、仮数が全部 1、c が a×b をほぼ打ち消す場合などに偏らせている。

```sh
cd viz/core
cargo run --release --bin difftest_mau -- fvfma 10 1   # 命令 / 回数 / シード
```

## SDM どおりだった挙動

- 丸めは最近接偶数丸め（RNE）で、FMA の丸めは1回だけ。
- 単精度の積は、仮数の下位5ビット同士の部分積を省き、省いた部分が 0 でなければ 2⁻³⁸ を足す（倍精度は下位16ビット、2⁻⁷⁴）。
  SDM の例「(2²⁰+1)² − 2⁴⁰ → 0x4a000010」も再現する。
- 指数が上に溢れたら ∞、下に溢れたら 0（非正規化数にはならない）。
- 出力の正規化：0 と ∞ は仮数を全部 0 にし、0 の符号は必ず + にする。

## SDM に書かれていない挙動（エミュレータで確認）

| 項目 | 挙動 | 確認した命令 |
|---|---|---|
| ∞ × 0 | 0 | `fvmul`, `fvfma` |
| ∞ + (−∞) | +∞ | `fvadd`, `fvfma` |
| 積に比べて c が極端に小さい | 積の指数 − c の指数 ≥ 43（単精度）または 90（倍精度）のとき、c を 0 とみなす。どちらも「部分積を省かない上位ビット数 + 仮数ビット数 + 2」（18+23+2、36+52+2） | `fvfma`, `dvfmau` |

3つ目は、積がちょうど丸めの中間値になるときにだけ結果に表れる。
例：1.5 × (1 + 2⁻²³) − 2⁻⁴³ は、厳密には切り下げになるはずだが、エミュレータは c を無視して偶数側に切り上げる。

## 一致を確認した範囲

| 命令 | 件数 | 不一致 |
|---|---|---|
| `fvfma` | 約56万 | 0 |
| `fvmul` / `fvadd` / `fvpassa` | 各約6.5万 | 0 |
| `dvfmau` | 約28万 | 0 |
| `dvmulu` / `dvadd` / `dvpassa` | 各約3.3万 | 0 |

## 未確認

- 半精度（`hv*`）、入力の精度拡張（`e`）と縮減（`r`）、出力の丸め（`r`）、入力の符号反転（`-`）
- ブロックフロート化（`*bfn` / `hbfe`）と行列積（`*mfma` / `*mmul`）
- ALU の浮動小数点系命令（`rsqrt`、`floor`、`ftoi`、`max`/`min`）
- `d set` で2長語（`$llm` など）を指定したときのアドレスの進み方。2個目以降の単位が想定と違う位置に書かれた
