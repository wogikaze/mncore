# MN-Core 2 数値演算・実行の実測メモ

`viz/core` のシミュレータが公式エミュレータ（`gpfn3_package_main`）とビット単位で一致するように、仕様（SDM）に書かれていない挙動を実験で確かめた記録である。

一次資料は公式の開発者マニュアル（SDM）とする。
README のリンク先の PDF を `judge/sdm/` に置いている（git 管理外）。
数値演算の定義は SDM の4章「出力の正規化」「RRN」「ベクトル積和演算」「ブロックフロート化」「行列ベクトル積和演算」にある。

## 確認の方法

| ツール | 内容 |
|---|---|
| `difftest_mau` | MAU のベクトル命令1種類を、ランダムな入力で大量に比べる |
| `difftest_prog <problem dir>` | 問題の解答を、テストケースごと両方で実行し、出力と4つの PE の全メモリを比べる |
| `difftest_fuzz [runs] [seed] [n]` | ランダムな PE 命令列を生成して比べる。不一致が出ると原因の命令群まで二分探索し、プログラムを `/tmp/fuzz_fail_*.vsm` に保存する |
| `difftest_file <file.vsm>` | 1つの VSM ファイル（`d set` / `d get` を含んでよい）を両方で実行して比べる |

```sh
cd viz/core
cargo run --release --bin difftest_fuzz -- 10 1 40
```

入力は、ゼロ、無限大、指数の端、仮数が全部 1、c が a×b をほぼ打ち消す場合などに偏らせている。

## SDM どおりだった挙動

- 丸めは最近接偶数丸め（RNE）で、FMA の丸めは1回だけ。
- 単精度の積は、仮数の下位5ビット同士の部分積を省き、省いた部分が 0 でなければ 2⁻³⁸ を足す（倍精度は下位16ビット、2⁻⁷⁴）。
  SDM の例「(2²⁰+1)² − 2⁴⁰ → 0x4a000010」も再現する。
- 指数が上に溢れたら ∞、下に溢れたら 0（非正規化数にはならない）。
- 出力の正規化：0 と ∞ は仮数を全部 0 にし、0 の符号は必ず + にする。
- ブロックフロート化（SDM 4.4）と行列ベクトル積（SDM 4.5）の手順。

## SDM に書かれていない挙動（エミュレータで確認）

### ベクトル積和・行列ベクトル積の加算器

| 項目 | 挙動 |
|---|---|
| ∞ × 0（ベクトル） | 0 |
| ∞ + (−∞) | +∞ |
| c の位置合わせ | 加算器の最下位桁は「積の指数 − K」の位置にある。c のうちそれより下のビットは切り捨て、切り捨てたものが 0 でなければ最下位桁に 1 を立てる（sticky ジャム）。c の最上位ビットが最下位桁より2桁以上下なら、c 全体を捨てる |

K は、積の部分積のうち残る最小の桁である。

| 命令 | K | c を捨てる「積の指数 − c の指数」 |
|---|---|---|
| ベクトル単精度（`fv*`） | 18 + 23 = 41 | 43 以上 |
| ベクトル倍精度（`dv*`） | 36 + 52 = 88 | 90 以上 |
| 行列 疑似単精度（`gm*`） | 18 + 18 − 2 = 34 | 36 以上 |
| 行列 単精度（`fm*`） | 18 + 23 − 2 = 39 | 41 以上 |
| 行列 倍精度（`dm*`） | 36 + 52 − 2 = 86 | 88 以上 |

行列の「積の指数」は、行と x それぞれのブロックの共通指数の和である。
内積が厳密に 0 でも、共通指数が大きければ c は捨てられる。

例（疑似単精度、内積 0、行と x の共通指数の和が 35）：c = 1.0 は 2.0 に、c = 5.0 は 6.0 に、c = 0.75 は 0 になる。

### 行列ベクトル積の特別な値

| 条件 | 結果 |
|---|---|
| 行または x のブロックの共通指数が 0（全要素が指数 0） | 内積は 0（もう一方が ∞ のブロックでも） |
| それ以外で、行または x のブロックの共通指数が最大値（∞） | 符号・仮数・c に関係なく +∞ |
| 有限値どうしの内積のオーバーフロー | 符号つきの ∞ |

### ブロックフロート化

- `hbfe`（拡張表現）では、値が 0 の入力と、仮数がアンダーフローした要素は、指数部も 0 になる（`hbfn` では共通指数）。
- 半精度以外のブロックフロート化（`dbfn` / `fbfn` / `gbfn`）では、出力2長語の下位側の長語は 0 になる（SDM の表は「第1入力の下位側をそのまま出す」）。

### ALU

- `msl` / `msr` の出力2長語の下位側の長語は 0 になる（PE 間で動くのは1長語だけ）。
- `rsqrt` の結果は、入力の指数の偶奇と仮数の上位4ビットだけで決まる。0 と ∞ は特別扱いされず、符号は無視され、出力の符号は常に +。
  - 出力の指数 = バイアス + (バイアス + 1) / 2 − 1 − ⌈入力の指数 / 2⌉（単精度 190、倍精度 1534、半精度 46 から ⌈e/2⌉ を引く）
  - 出力の仮数 = 次の5ビットを仮数の先頭に置いたもの

    | 指数 | 仮数の上位4ビット 0〜15 に対する5ビット |
    |---|---|
    | 偶数 | 13, 11, 10, 9, 8, 7, 6, 5, 4, 4, 3, 2, 2, 1, 1, 0 |
    | 奇数 | 31, 30, 28, 26, 25, 23, 22, 21, 20, 19, 18, 17, 16, 15, 14, 13 |

### 書き込みマスク

- 長語単位のマスクでは、上位側の長語を4つの半語として、フラグのビット3〜0を上位の半語から順に対応させる。
- 下位側の長語は、フラグが全部0でも丸ごと書く。以前の「全部0なら書かない」という記述と実装は誤りだった。
  非ゼロの旧値と新値を用いた768サイクルの公式比較で確認し、12件の不一致を修正した。
  入力・期待値・ツールのハッシュと当時の誤ったモデルは`proofs_lean/evidence/masks/`に保存している。

### L1BM の縮約

- 16要素の縮約は、連続する4つの MAB（0〜3、4〜7、…）ごとに1段目を行い、その4つの結果を2段目で縮約する。
- 半精度の浮動小数点数縮約（`l1bmrhfadd` など）は、単精度に拡張して1段目を単精度に丸め、2段目で半精度に丸める。
- 精度拡張（`e`）と精度縮減（`r`）を使っても、L1BM 上の並びは PE ごとの元の並びのまま。SDM 3.6.8.4〜3.6.8.5 の並べ替えは、縮約回路の内部の順番の説明だった。

### MV 命令と DRAM / PDM

- エミュレータは MV 命令を発行と同時に完了させる。値の上では `wait` は何もしない。
- ジャッジは DRAM と PDM を 0 で初期化してエミュレータを実行する（`--offchip-memory-init zero`）。
- エミュレータの `d get $p`（PDM の表示）は、実際には DRAM の同じアドレスを表示する。PDM そのものは正しく動いていて、後続の MV 命令は PDM に書いた値を読める。差分テストでは PDM の表示を比べない。

### 実行時エラーは遅延評価

エミュレータは、次の誤りを「その値が実際に使われたとき」だけエラーにする。

| 誤り | エラーになる時点 |
|---|---|
| 前のステップに該当する演算器の命令がないのに `$aluf` / `$mauf` を読む（"IALU is disabled" など） | その結果をメモリに書くとき（マスクで書き込みが無効なら起きない）、または次のステップでそのフォワーディングレジスタを読むとき |
| 行列ベクトル積の入力が不正なブロックフロート（ブロック内で指数が違う。半精度は 0 も可） | 同上 |

結果を `$nowrite` に捨てるだけなら、エラーにならない。
シミュレータは、不正な結果に「毒」の印を付けて伝播させ、同じ時点でエラーにする。
マスクレジスタへの書き込みはデータ値ではなく別に生成したフラグを使うため、
無効フォワーディングのデータエラーを強制しない。ALUコピーではフラグ0が書き込まれた。
以前のシミュレータがこの書き込みでもエラーにしていた点を修正した。

行列転置読み出しの`$mreadf`は、通常ステップに行列読み出しがない場合、エラーでなくゼロが読める挙動を確認した。
以前の値を保持するわけではない。nop/noforwardの場合は以前の値を保持する。
これはマニュアルの一般的な「直前のステップ」という説明との対応が未解決であり、
全フォワーディングを一律に無効化する根拠にはしない。

L1BM→PEの`$lbf`は通常ALU/MAUステップを挟んでも以前の値を保持し、次のL1BM転送で更新する。
noforward付き転送では以前の値を保持する。
一部のソースはアセンブラの型推論が拒否するため、受理された命令断片の語を変更せずに挿入して
11種類の語列を公式エミュレータで確認した。ローカル実装の一律無効化を修正した。
これは符号化語列での観測であり、拒否されたVSMソースの合法性を主張しない。

### デバッグ文

- `d get $lt` は各サイクルの上位側の長語だけを表示し、5個目からは先頭に戻る。T 全体を見るには `d get $llt <n>` を使う（1行に2長語）。
- `d set $lt <n>` は各サイクルの上位側の長語に、`d set $llt <n>` は両方の長語に書く。
- `d set $llm`（2長語）は、2個目以降の単位が想定と違う位置に書かれた（未解明。テストケースは使っていない）。
