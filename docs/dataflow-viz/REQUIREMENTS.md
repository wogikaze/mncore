# MN-Core データ移動可視化サイト 要件定義（ドラフト）

## 1. 目的

MN-Core 2 の VSM プログラムが、メモリ階層の中で大量のデータをどう動かしているかを、SVG アニメーションで見えるようにする。

既存の `gif_generation/` にある公式動画（`.smv`）は、命令1個の挙動を示す短いデモである。
本サイトは、プログラム全体を通したデータの流れを扱う。

用途は次の3つ。

| 用途 | 欲しいこと |
|---|---|
| 自分の解答のデバッグ | どのステップで、どのデータが、どこからどこへ動いたかを追える |
| 性能のボトルネック把握 | 転送量、ステップ数、並列度、階層ごとの混み具合が分かる |
| 学習・説明用 | 転送パターンをスクロールで読み進める解説として見せられる |

## 2. 対象のハードウェアモデル

可視化する階層は次のとおり（`docs/mncore_llm` の 1.1 構成による）。

```
Host ── PDM(×4 グループ) ── DRAM(×4)
           │
        L2BM (×8, 2 個ずつ 4 グループ)
           │
        L1BM (×64, L2B あたり 8)
           │
        MAB (×1,024, L1B あたり 16) ── MAU
           │
        PE (×4,096, MAB あたり 4): LM0 / LM1 / GRF0 / GRF1 / T / 行列レジスタ
```

- 階層の個数や容量は設定データとして持ち、コードに直接書かない。
- PE の内部（LM0/LM1/GRF/T/MAU）も対象に含める。
  `problems/*/main.vsm` は PE 内の転送（`$lm`→`$aluf`→`$ly`→`gmmul` など）が大半を占めるため。

## 3. 入力：VSM の静的解析

### 3.1 前提

- VSM は制御構造のない、1本の命令列である。そのため静的解析だけで、各ステップの転送をすべて復元できる。
- 入力は `problems/*/main.vsm` と `fx_export` が出力する VSM の両方とする。

### 3.2 解析の内容

1. VSM の1行を1ステップとして、命令列を読み込む（`nop/N` などのステップ数の扱いは仕様で確認する）。
2. 各命令を「転送イベント」に変換する。
   - 送り元：階層、ユニットの集合、アドレス範囲
   - 送り先：同上
   - 語数、精度（倍精度・単精度・半精度など）
   - 転送の種類（unicast / bcast / distrib / concat / reduce / multicast など）
   - 演算を伴う場合はその種類（MAU の積、ALU 演算）
3. 対応する命令の範囲（段階的に広げる）
   - **M1:** PE 内の転送（`$lm` / `$ln` / `$r` / `$s` / `$t` / `$aluf` / `$mauf`）と行列レジスタ（`*mwrite` / `*mread` / `*mmul`）
   - **M2:** L1BM↔PE、L2BM↔L1BM（`l1bmp` / `l1bmd` / `l1bmm` / `l2bmb` / `l2bmd` / `l2bmr` など）
   - **M3:** MV 命令による DRAM/PDM/L2BM 間の転送（`mvp` / `mvb` / `mvd` / `mvr` 系）
4. 解析できない命令は「未対応」として一覧に出し、表示上はそのステップを空けたまま処理を続ける。

### 3.3 解析結果の形式

- 転送イベントの列を JSON に書き出す。描画はこの JSON だけを入力とし、パーサとは切り離す。
- 書き出した JSON はそのまま静的ファイルとして配信でき、学習用のストーリーにも使い回せる。

## 4. 表示

### 4.1 ズームによる粒度の切り替え

| ズームレベル | 表示 | 表現 |
|---|---|---|
| チップ全体 | DRAM / PDM / L2BM ×8 / L1BM ×64 | 経路の太さと粒子の密度で、転送量を表す |
| L2B / L1B | 選択したブロックの子ユニット | ユニット単位の流れ。bcast や reduce の分岐・合流が見える |
| MAB / PE | 選択した PE のローカルメモリ | ワード単位。アドレスを格子で示し、値も表示する |

- 表示中のレベルの要素だけを DOM に置き、4,096 PE を常時すべて描画することはしない。
- 隣り合うレベルの間は、拡大・縮小のアニメーションでつなぐ。

### 4.2 時間軸

- ステップ単位のタイムライン（再生、一時停止、コマ送り、シーク、再生速度）。
- 転送量と稼働率をスパークラインで示し、混雑しているステップをすぐ見つけられるようにする。
- タイムラインの各ステップは、VSM の該当行とハイライトで連動させる。

### 4.3 二つのモード

1. **Explorer モード**（デバッグ・性能分析）
   - VSM をドラッグ＆ドロップ、または `problems/` から選んで読み込む。
   - タイムラインで操作し、ユニットやアドレスをクリックすると、そこを通ったデータの履歴を表示する。
   - 階層ごとの転送量、ステップ数、並列度を集計して表示する。
2. **Story モード**（学習・説明）
   - スクロールに合わせてアニメーションが進むスクロールテリングにする。
   - 説明文の各節に「どのイベント列を、どのズームレベルで見せるか」を割り当てる。
   - 例：「256×1024 の行列を DRAM から PE に配る」「MAU で行列積を計算する」

## 5. 技術スタック（案）

| 役割 | 候補 | 理由 |
|---|---|---|
| ビルド | Vite + TypeScript | VSM パーサとイベントの型を厳密に書ける。静的サイトとして出力できる |
| UI | Svelte 5 | SVG を宣言的に書きやすく、ランタイムが軽い |
| アニメーション | GSAP（ScrollTrigger / MotionPath） | 複雑なタイムライン合成とスクロール連動の事実上の標準。全プラグインが無料 |
| レイアウト計算 | d3-scale / d3-hierarchy | ツリーの配置と量のスケーリング |
| テスト | Vitest | パーサの単体テスト（`problems/` の VSM を使う） |
| 公開 | GitHub Pages | 静的にビルドしてそのまま公開する |

- 粒子の数が多すぎて SVG で描き切れない場合に限り、粒子の層だけを Canvas で重ねる。どこからそうするかは計測して決める。

## 6. 非機能要件

- `fx_export` の出力（10万行規模）を読み込んでも、解析が数秒以内で終わる（解析は Web Worker で行う）。
- 通常のズームレベルで 60fps を目標にする。
- 新しい命令への対応は、パーサにルールを1つ足せば済むようにする。

## 7. スコープ外（当面）

- エミュレータとの連携（実行トレースの取り込み、値の正確なシミュレーション）。
  静的解析で値を出せるのは即値やロードの追跡まで。正確な値の確認は将来の拡張とする。
- サイクル単位の精密なタイミング（パイプラインやハザード）。
