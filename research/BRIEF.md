## 検証コマンド

```sh
# 高速（ネイティブシミュレータ、数秒）: 語数・不一致数
python3 tools/fbcheck.py candidate.vsm

# 公式ゲート（assemble3 + gpfn3 + testcase の d getd 期待値）
python3 tools/fbverify.py candidate.vsm      # 高価。最終主張の前に必須。

# 公式ジャッジ（judge.py 経由、1.3 秒。最終ゲート）
python3 tools/fbverify.py candidate.vsm
```

`tools/fbcheck.py` は testcase の `d getd $d<i>n0` 期待値と直接比較する。
語数はアセンブル後の `j`/`m` 行数。

## 制約

- `d set` 禁止、`d get` 等デバッグ命令は提出物に含めない。
- 採点初期状態を勝手に強化しない（DRAM はゼロ初期化前提でよい。非ゼロ初期化に依存する解は不可）。
- 出力は Group 0 DRAM 先頭 32,766 バイトの完全一致。

## 既知の事実（過去研究の要約。鵜呑みにせず再検証可）

### 93 語解の構造
- 座標 `b = (l2bid,l1bid,peid)`, `m = 8b`。
- 位置 `s0` を `{0,32,408,4672}` と比較して桁域を選択。
- `b`（ブロック先頭数値, float）と `c`（位相, `fftoi`, `lr18`）を計算。
- T 連鎖で `w*k + {8,13,23,33,33}` を `lsub` マスクで選択（11 ALU）。
- `$mt[43,41]` から `v1/v2` を取得し数字を描画後、Fizz/Buzz 文字で上書き。
- pack は 6 ALU で 8 バイトを構築。転送は `l1bmd→l2bmd→mvd→mvp`（2 MV）。

### 検証済み技法
- FMA mod 15: `base=0x452A0000`, `K=0x4488A854` で `(F>>32)&15 == n%15`（n≤6334 全数）。
- `iand 120` による 3/5 倍数判定: `iand(fvmul(n,1/3),120)==0` ⟺ 3 の倍数。

### 否定済み（反例・理由つき。ただし前提が変われば再検討可）
- 局所変換・移設・削除（49,000+ 候補, 0 勝）。
- 転送短縮: `mvd` 省略は 4080 語不一致。直接 `mvp` 不可。
- 座標構築の短縮: 7 サイクル置換、9 ALU 下限と主張。
- 定数の MAU 生成: GRF0 ポート衝突。
- `mod 79` の FMA 化: 79 が 2 冪を割らないため不可。
- 79 バイト周期テンプレート放送: 語境界非整合＋数字が毎周期変化。

### 実装上の注意
- `d getd` の dump アドレスは*ワード*アドレス（長語は 2 ずつ進む）。
- 2 長語動作 `no` の命令は LSB 長語を素通りさせる（msl/msr/d/f/g bfn は errata で 0 埋め）。
- 採点は errata 込みの公式エミュレータ挙動で行われる。
