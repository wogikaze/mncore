2. 課題：FizzBuzz の文字列を DRAM に書く
- 1〜6334 の FizzBuzz を \n 区切りで連結した 32,766 バイトを Group 0 の DRAM 先頭へ書く
- 出力は 8 バイトの長語 × 4096 個。例：1〜3 なら先頭の長語は 0x310A320A46697A7A（1\n2\nFizz）
- スコア：score = j + m（j = PE 命令の語数、m = MV 命令の語数。小さいほど良い）
- 制約：d set 禁止、デバッグ命令を入れない、DRAM はゼロ初期化だけを前提にする
- 判定：fbcheck.py（高速シミュレータ）→ fbverify.py（公式ジャッジ）

3. 1行に4つの欄。行数は ALU欄と MAU欄の埋まり方で決まる
- ALU欄：ALU演算か imm のどちらか1つ／MAU欄：浮動小数の積和など1つ／L1BM欄：座標の往復、4レーンの OR、定数の置き場／L2BM欄：末尾の転送
- 47語 = 計算40行 + 末尾7行（nop ×3、l2bmd ×2、mvd、mvp。全版で共通。MV 命令は mvd と mvp の2語）
- 4096 PE × 4サイクル = 16,384 レーン。4レーンで 8 バイトの長語1個を作る

4. 1レーンの計算：m から3系統に分かれ、1つに戻る（フロー図）
- ① 長語の番号 B（PE番号から、0〜4095）→ ② トークン番号 m（B の1次式3本の最小 + レーン番号 k）
- ② から3系統：3a 数字の文字列（n = floor(15(m+1)/16)、桁を取り出して詰める）／3b 表引き（m mod 16 で LM0 の表を引く：Fizz・Buzz の文字列と位置の補正値）／3c 位置（先頭位置から左右のシフト量を作る）
- 3a と 3b → ④ 選択（fmax(数字, 表) → fftoi。表に Fizz・Buzz がある番号では文字列のほうが常に大きい）
- ④ と 3c → ⑤ ullsr / llsl でずらし、4レーンを OR（l1bmr4lbor）、末尾7行で DRAM へ
- 注：トークン = 数または Fizz・Buzz と改行。FizzBuzz は2つに分けるので、15個の数ごとに16個

11. 実測で確かめたハードウェア規則（2列×4枚のカード）
- 書き込みは6サイクル後に完了（同番地なら3行後）→ /1000 マスクで定数を2行後に読む
- マスクは1行に1種類。/1000 と /$imrN は同居不可 → サイクル別に書く定数（49語）
- LM は同じ行で読み書き不可。書くと2行読めない → 表と変数の置き方を縛る
- imm は LM0 に触る命令と同じ行に置けない → LM0 を使う MAU 命令の配置を縛る
- imm は3つ、MAU は4つのファイルへ同時に書ける → 1つの値を複数のファイルに置く（51語）
- L1BM は64の倍数番地。格納後2行は読めない → 定数の置き場に使う（50語）
- imm の値は次の行で $aluf として読める → レジスタを通さない定数（49語）
- ALU の fmax は T 間接参照で LM0 を読める → 数か文字列かを1命令で選ぶ（51語）

12. 46語が難しい理由：3つの下限がすべて40行（積み上げ横棒3本、40の位置に縦線）
- ALU欄：imm 21 + ALU命令 17 + 空き 2 = 40
- 座標計算の前：前置き imm 7 + 座標6命令と最短の鎖27行 33 = 40
- MAU欄：MAU命令 36 + 空き 4 = 40
- 46語には3つを同時に1ずつ下げる必要がある。46語（計算39行）は、ポートの規則をすべて外したモデルでも解なしと証明した
- 効かなかった手：定数導出の総当たり、最小値を取ってから丸める推定器、位置直線の傾き0
