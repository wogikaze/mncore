# 8.sumcol: 8 語から 6 語へ

## 結果
`best.vsm`（`c6a.vsm` と同じ）は 6 語（j=5, m=1）である。公式 judge は `ACCEPTED!! score=6 j=5 m=1 bytes=96` を返した。出力は記録解とビット単位で一致するので、golfcheck も OK を返す。

```
ipassa $peid $t
nop
l1bmr4ffadd $llmt0v $llb64
nop
l2bmrffadd $lb16 $lc16
mvrffadd/n64 $lc64 $d0
```

## 1. 記録解（8 語）の仕組み
```
imm ui"0x00000002" $nowrite
llsl $mabid $aluf $t
nop
l1bmr4ffadd $llmt0v $llb0
nop
nop
l2bmrffadd $lb0 $lc0
mvrffadd/n64 $lc0 $d0
```
- 入力は全 MAB に同じものが置かれている。各 PE の lm[4r..4r+3] には、行 r のうちその PE が受け持つ 4 列（2 長語）が入っている。行 r は PE 内で 4 行あり、その 8 L1B 倍、さらに 8 L2B 倍で全 256 行になる。
- 行 1–2 で T=4m（m は MAB 番号）にする。行 3 は T を読めるまでの待ちである。
- 行 4 は `l1bmr4ffadd $llmt0v` による 2 長語の 4x4 縮約である。MAB m は lm[4m..] を読む。MAB0..3 が行 0..3 を読み、MAB4..15 は 16 番地以降のゼロ領域を読む。4x4 縮約は mab&3 の方向に足すので、PE 内 4 行の和が lb0..7 にでき、ほかのグループには 0 が入る。PE 内の加算を ALU なしで済ませる手法である。
- 行 5–6 は L1BM→L2BM の待ち（10 サイクル規則）である。行 7 の `l2bmrffadd` で 8 L1B を足す。行 8 の `mvrffadd/n64` で 8 L2B を足して DRAM に書く。これが MV の 1 語である。

## 2. 効いた変更
### 2.1 imm を消す（8→7、`c7a.vsm`）
`imm 2` と `llsl $mabid` の 2 命令を `ipassa $peid $t` の 1 命令にした。
- `$peid` を T に入れると T=4m+p になる。
- 2 長語を T 間接で読むと番地が 4 の倍数に切り捨てられるので、実効番地は 4m になる（10.sumrow で実測済みの規則）。
- 結果は記録解と完全に同じになる。

### 2.2 L1BM→L2BM の待ちを 1 行削る（7→6、`c6a.vsm` = `best.vsm`）
仕様 3.6.3.7 では、PE→L1BM で書いた番地を L1BM→L2BM で読むには、発行サイクルの差が 11 以上必要である。この規則はステップ単位ではなく、命令内のサイクル単位で判定される。
- 2 長語の `l1bmr4` は、サイクル c に dst+32c からの 32 長語を書く。有効なデータ（グループ 0 の 8 長語）は dst の位置に入り、サイクル 0 で書かれる。
- `l2bmr` は、サイクル c に addr_b+16c からの 16 長語を読み、addr_c+16c に書く。
- そこで有効データを lb64 に置いた（dst=64）。そのうえで `l2bmrffadd $lb16 $lc16` とすると、lb64 を読むのは l2bmr のサイクル 3 になる。間の nop が 1 行でも、差は 4·2+3−0 = 11 で規則を満たす。
- 結果は lc16+48 = lc64 に入る。MV の L2BM 番地は 64 の倍数でなければならないので（アセンブラのエラーで確認）、lc64 になるように addr_c=16 を選んだ。
- `mvrffadd/n64 $lc64 $d0` は l2bmr の直後の行に置いてもハザードにならなかった。
- l2bmr のサイクル 0–2 が読む lb16..63 は誰も書かない領域（ゼロ）で、その結果の lc16..63 は MV が読まない。

## 3. 試したが駄目だった案
- T の待ちを消す（`ipassa $peid $t` の次の行で T 間接読み出し、`c5t.vsm`）: `A racy memory read at T`。T 間接で読むのを Flat 指定でサイクル 3 だけにしても同じエラーで、T の待ちは行単位で判定される（`c6b.vsm`）。
- T の代わりに BAR を使う（`ipassa $peid $mb`、`c5bar.vsm` と `c6bar.vsm`）: 次の行でも、1 行空けても `racy memory read at LM0 address 0` になる。BAR は T より遅い。
- MV の読み出し番地を lc48 にする: `L2BM address must be aligned to the multiple of 64`。
- l1bmr→l2bmr の nop を 0 にする: 差は最大 4+3 = 7 サイクルで、必要な 11 に届かない。

## 4. 5 語にならない理由（下限）
1. **MAB ごとに違う番地を読む必要がある。** 入力は全 MAB で同じである。PE 内の 4 行（番地の違い）を足せる縮約は MAB 方向（L1BM 縮約）にしかない。
   - PE 方向は結合で、和にならない。
   - L1B と L2B の方向は、すでに行インデックスの別の軸に使われている。
   - サイクルが違えば書き込み先の番地も違い、l2bmr と mvr もサイクル（番地）ごとに独立なので、サイクルをまたいで足す手段はない。
   - よって MAB ごとに番地を変える必要があり、その手段は T 間接か BAR しかない（`j` は PE 番号にしか依存しない）。ALU で PE 内の加算をすると 4 行以上かかる（main.vsm）。
2. **T（BAR）は書いた次の行では読めない**（アセンブラが racy として拒否する）。したがって設定に 1 行、待ちに 1 行が要り、縮約は早くても 3 行目になる。
3. **L1BM→L2BM には 11 サイクル以上の差が要る。** 1 ステップは 4 サイクルなので、nop 1 行（差 8+3）が最小である。今の解はすでにこの最小を使っている。
4. **L2BM から DRAM への MV は 1 語必須**で、l2bmr の直後の行に置ける。
以上で 1+1+1+1+1+1 = 6 行が下限になる。5 行にするには T を書いた次の行で T 間接読み出しをするしかなく、アセンブラが拒否する。
