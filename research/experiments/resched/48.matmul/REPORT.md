# 48.matmul-tra-pkg-lmdram-16-256-1024 短縮の調査

結論：61 語（j=56, m=5）を 58 語（j=55, m=3）にした。
`best.vsm`（= `c6.vsm`）は run_problem と `judge.py --dirty` の両方で `ACCEPTED!! score=58 j=55 m=3 bytes=3167` になった。golfcheck でもビット一致する（足す順序は変えていない）。
効いたのは次の 2 点である（それぞれ単独でも両 judge で確認）。
- MV の末尾を DRAM 間接参照（DAR）で 5 語から 3 語にした（−2、`c5.vsm` = 59）。
- T を 1 命令で作り、行列書き込みの鎖を 1 行前に詰めた（−1、`sh1.vsm` = 60）。

きっかけは `tools/slack.py` の順位で、この問題がデータの流れの下限から最も離れていた（61 対 37）。
実際には K の分け方のせいで転送量は減らせず、縮んだのは MV の末尾と先頭の鎖だった。

## 1. 記録解の動作と、各段で動く量
- **K の分け方**
  - K=256 は 8 L2B × 32 に分かれている。L2B の中では、どの MAB も同じ 32 個の K をすべて持ち、自分の 8 列（N 方向）を受け持つ。
  - したがって L2B の中では、K について足し合わせられるものがない。L1BM（l1bmr）や L2BM（l2bmr）で縮約しても量は減らない。
  - 39 で l2bmrffadd が効いたのは、K が L1B と MAB にも分かれていたからである。
  - 各 L2B の部分和は 16×1024 全体で、8192 長語ある。この部分和はどの L2B でも異なる。
- **計算**
  - B は 8×8 の行列レジスタで転置する。生の B の gmwrite → gmread → gbfn → B^T の gmwrite という順になる。
  - A は MAB ごとに T 間接参照で一部を転置する。gbfn をかけ、l1bmd で集め、l1bmm で GRF1 に放送する。
  - gmmul/gmfma は 16 本。1 つの出力行群は、K を 4 つに分けたスライスの 4 演算で完成する。
- **各段で動く量（1 L2B あたり）**

| 経路 | 量 | 命令 |
|---|---|---|
| PE→L1BM | 1024 長語/L1B | l1bmd 4 本 |
| L1BM→L2BM | 8192 長語 | l2bmd 32 本（64 長語/サイクル、256 長語/行） |
| L2BM→PDM | 8 L2B を mvrffadd で縮約して 8192 長語 | |
| PDM→DRAM | 2048 長語 × 4 グループ | mvp 4 本 |

- **語数の内訳**：先頭 23 行（最初の l2bmd は 24 行目）、l2bmd 32 行、nop 1 行（L1BM→L2BM の直後に MV を置く場合の待ち）、MV 5 語。

## 2. 試した案と結果

### (a) MV 5 語 → 3 語（採用、−2）
- 直接 DRAM に書く 1〜2 語の案は、どれもデータの中身の制約で成り立たない。
  - 対象は `mvr` L2BM→DRAM、`mvd` PDM→DRAM、`mvr4` である。
  - これらは 64 長語の塊のうち、16 長語の slot g をグループ g の DRAM に送る。
  - l2bmd が書いた塊では、slot g が L1B 2g と 2g+1 から来る。
  - L1B l が持つのは C[全行][その L1B の列] で、グループ g が必要とするのは C[4g..4g+3][全列] である。
  - L1B の間でデータを入れ替えるには、l2bmi（16 長語/サイクル）か L2BM の往復が要り、何十行もかかる。
- `mvp $p0@0 $d0`（グループを書かない PDM→全 DRAM）はアセンブラが拒否する（"Group ids … invalid"、`t1.vsm`）。
- 採用した 3 語：
  ```
  mvrffadd/n8192 $lc0 $p0@0
  mvb/n8192 $p0@0 $lc0
  mvp/n8192nd16 $lc0@.0 $di0
  ```
  - 縮約した C を全 L2BM に放送し、各グループの L2B.0 から自分の DRAM へ全量 8192 長語を書く。
  - 書き先は DAR（グループごとにある）で振り分ける。自グループの行は d0..2047 に入り、他グループの行は d2048..8191（ゴミ置き場）に入る。
  - judge は d0..2047 だけを見る。
- DAR の仕様（実測）
  - `nd` は 16 までしか書けない（32 以上は "too big"）。
  - DRAM 番地は DAR[M+i/16] + i%16 で、単位は 16 長語である。
  - したがってエントリ 1 個で 256 長語を受け持ち、32 エントリ（l2bmdarw 8 ステップ）が要る。
  - 1 長語の上位 32 ビットが偶数エントリ、下位が奇数エントリになる。
  - l2bmdars の L2BM 番地は 64 の倍数でなければならない。
  - l2bmdars は l2bmd と同じ行に置けない。l2bmdarw は置ける。
- DAR の値
  - エントリ e に、その塊の本来の位置（16 長語単位で 16e）と 128g の XOR を入れる。g はグループ番号である。自グループの塊なら 0..112、他グループの塊なら 128 以上になる。
  - 1 長語の上下 2 語で 16 だけ違う値が要る。そこで l2bmd の書き先を塊番号 c → c^1 と入れ替えた（"swap"）。こうすると値は (32j+16, 32j) ⊕ 128g になり、`immu i"16"`（上位語だけ 16）との OR 1 回で作れる。
  - PE での計算：`ipassa $l1bid` を `ilsl $peid $aluf $ln200` に渡す。L1B5 の PE なら l1bid=5 なので、imm を使わずに 32·peid が得られる。続けて `imm i"6"`、`ilsl $l2bid $aluf`（L2B.0 では 64·l2bid=128g）、`ixor … $t`、`immu i"16"`、`ior`。
  - 転送：`l1bmd $aluf $lb4096`、2 行後に `l2bm@5 $lb4048 $lc8144`、次の行に `l2bmdars $lc8192@.0 $dar0;l2bmdarw`、その後 l2bmdarw を 7 行に重ねる。
- 置き場所の制約（すべて実測）
  - l1bmd と l1bmm は同じ行に置けない（bmode 衝突）。
  - l1bmd の直後の行に l1bmm は置けない（"L1BM_Local port unavailable"）。
  - そのため DAR 用の l1bmd は、最後の l1bmm の次の行（記録解の 20 行目）しか空いていない。
  - PE→L1BM から L1BM→L2BM までは 11 サイクル要る。2 行後の l2bm@ で使えるのはサイクル 3 の 16 長語だけである。
  - 64 エントリ版（`c1`/`c4`、16 長語 × 2 サイクル）は racy で落ちた。32 エントリの swap 版がちょうど収まる。
  - imm は LM0 に触る行に置けない。
- 試作 `p1.vsm`（93 語）で、DAR の方式そのものを公式 judge でも確かめた。

### (b) 先頭を 1 行縮める（採用、−1）
- 記録解は `ipassa $mabid` と `iadd` の 2 行で T=2·mabid を作っている。これを `ipackbit $mabid $lr200 $t` の 1 行にした。
  - dirty では MSB が不定なので、T は 2m+b になる。1 長語の T 間接読み出しは番地を偶数に切り捨てるので、結果は変わらない。
- A の gmwrite（`$lmt0v16`/`$lmt64v16`）を 3・4 行目に詰め、それ以降を全体に 1 行前へずらした。
  - 行列書き込みの鎖（生の B 8 本、A 2 本、B^T 8 本）は 1〜18 行目に隙間なく並ぶ。
  - 最後の gm 演算が 19 行目、結果の l1bmd が 20 行目、最初の l2bmd が 23 行目になる。
- (a) と合わせた版では T が 4 行目まで A に使われる。そのため 32·peid は LM1 に置いた。

### (c) その他（効果なし、または不成立）
- **MV 前の nop を消す**：`c7_nonop.vsm` は racy で落ちた。mvr は最後の l2bmd が書いた領域も読む。32 本の l2bmd は全部 C のデータなので、最後の行を別の命令に替えられない。
- **K の縮約を前に寄せて量を減らす**：上のとおり、L2B の中に縮約できる K がない。部分和は 25 ビットの整数（|x|≤2^23）なので、1 長語に 2 つより多く詰めることもできない。B を L2B の間で動かすと、同じ 8192 長語が動くうえに MV と l2bmd が増える。
- **A の転置を gmwrite 1 本にする**：`$lmt0v32` を使えば 1 本で A 全体を覆える（MAB m が k=m/2+8c, h=m%2 を担当）。それでも gmread は 2 本要る。行列が 2 つしかなく、mread は 1 行に 1 本なので、行列書き込みの列に必ず空きが 1 行できる。行は縮まない。
- **半精度での転置**：精度拡張（`e`）は L1BM の縮約経路にしかない。pseudo-single の BF に戻すには L1BM を往復する必要があり、検討を打ち切った。

## 3. 下限
- **l2bmd 32 行**：L1BM→L2BM の書き込みは最大 64 長語/サイクルで、l2bmd と l2bmr2 がこの速さである。各 L2B が出す 8192 長語の部分和は、どの段でも減らせない。
- **先頭 22 行**：最初の出力行群は 4 つの B^T スライスすべてを必要とする。それまでに行列書き込みが 18 本要る。行列は 2 つ、mwrite は 1 行に 1 本なので、最後の書き込みは 18 行目より早くならない。その後 gm 演算 → l1bmd → 3 行後に l2bmd で、23 行目になる。最初の l2bmd は 32 長語/L1B をすべて読むので、サイクル単位の手法で前に寄せる余地はない。
- **nop 1 行**：MV の待ちで、上の (c) のとおり消せない。
- **MV 3 語**：全 L2B の縮約に 1 語、グループごとに違う中身を DRAM に分けるのに 2 語要る。DRAM に直接書く縮約や分配の命令は、slot と L1B の対応のせいで使えない。
- 合計 22 + 32 + 1 + 3 = 58。これより縮めるには、行列書き込み 18 本の鎖を短くする別の転置方法か、L1BM→L2BM をより速く運ぶ経路が要る。
