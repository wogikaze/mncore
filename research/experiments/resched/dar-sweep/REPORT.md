# DAR 間接参照・MV 削減の横展開（MV 2 語以上の全問題）

結論：48.matmul で効いた「DAR 間接参照で MV を減らす」手は、他のどの問題でも語数を減らさなかった。
対象は MV を 2 語以上使う 11 問（17, 18, 21, 22, 23, 26, 27, 39, challenge/16, 19, 20）で、すべて記録解のままである。
記録解は全問で run_problem と judge.py の両方で ACCEPTED を確認した（challenge の 3 問は Output 区切りを補った testcase で、--dirty なし。run_problem と同じ扱い）。

48 で効いたのは、(1) PE にしか作れないグループごとのずらし（DAR や l2bid）が要ること、(2) DAR の準備を隠せる空いた PE の行があること、の 2 つがそろっていたからである。
他の問題はどちらかを欠く。DL 問題はグループをまたぐ MV が slot g をグループ g に縛る。L2B ごとに 2 本に分けた MV は、PE 側の L2BM 命令が L2B を指定できないので 1 本にできない。16.count-up は出力がグループ 0 だけなので、グループごとの DAR が役に立たない。

## 測った事実
- PE 側の L2BM 命令は L2B を指定できない。`l2bmd $lc0@.0 $lb0`（DL 側）も `l2bmd $lb0 $lc0@.0`（UL 側）も、アセンブラが "L2B id must not be set." で拒否する（`17.dram-dl-256-16/a1.vsm`, `a2.vsm`, `18.dram-ul-256-16/a1.vsm`）。
  - 同じグループの L2B .0 と .1 に違う中身を置く（あるいは読む）には、MV を 2 つに分けるか、PE が $l2bid で値を変えるしかない。
- DAR の初期値は 0 である。DL 方向の間接読みも公式 judge で動く。`17.dram-dl-256-16/d0.vsm` は 1 本目の mvp を `mvp/n256nd16 $di0 $lc0@.0` にしたもので、`ACCEPTED!! score=5`（語数は同じ）。
- `mvr2iiadd/n512` で 2 つの L2B を 1 語で書く案（18、`a2.vsm`）：0 で埋めない限り値が重なり、2048 個が不一致になる。

## グループをまたぐ MV の制約（DL 方向）
- mvb（DRAM から）、mvb4、mvd（DRAM→PDM）は、64 長語の行の slot g に必ずグループ g の DRAM のデータを置く。DAR で変えられるのは、そのグループの DRAM の中でどの塊を読むかだけである。
- l2bmd は slot g を L1B 2g, 2g+1 に配る。したがってこれらの MV を通すと、L1B の組 g はグループ g のデータしか受け取れない。L2BM での縮約（mvr）も位置を保つので、この制約は残る。
- グループの境界を越えて位置を自由に決められる経路は 1 つしかない。DAR 付きの並列 mvp でグループごとに違う番地へ置き、mvr で足し合わせる方法である。

## 問題ごと
### 26.dram-dl-16-1024（39, MV 5）
- 3 語にする構成はある。
  - `mvp/n8192nd16 $di0 $lc0@.0`（並列）で、グループ g のデータを L2B(g,0) の [2048g, +2048) に置く。それ以外の部分は、DRAM の未使用域（0）を読ませる。DAR_g[e] = 16e xor 128g の 32 エントリを使う。
  - L2B(g,1) は 0 のままである。
  - 続けて `mvriiadd/n8192 $lc0 $p0@0` と `mvb/n8192 $p0@0 $lc0` を出す。
- これで MV は 5→3 で −2 になる。しかし DAR を書く作業はすべて MV より前に置く必要があり、隠せる PE の仕事がない（l2bmd は MV の後でしか動けない）。
  - 内訳：ALU で値を作る（3 命令以上）、l1bmd、2 行の待ち、l2bm、l2bmdars と l2bmdarw で 8 行。
  - 少なくとも 15 行増え、差し引き +13 以上の損になる。
- 一部を先に直接転送して重ねる案も検討した（グループ 0 の分を mvp と mvb で先に運び、l2bmd 8 行を DAR の準備と並べる）。この場合 MV は 2+3=5 語に戻る。
- 上の slot の制約から、DAR なしで 4 語以下にする経路もない。

### 17 / 21 / 22 / 23（DL、MV 2）
- L2B .0 と .1 で違うデータが要る。mvb2 は同じ中身を両方に書く。PE 側の l2bmd は L2B を選べない（拒否される）。
- DAR はグループ単位なので、同じグループの 2 つの L2B を区別できない。
- MV を 1 語にするには PE で $l2bid による選択が要り、行が増える。17 で `l2bmd@.c` 相当を数えても 5 で同じだった（しかもアセンブラが受け付けない）。

### 18 / 27（UL、MV 2）
- 1 語にするには `mvr2iiadd` を使い、L2B(g,0)=[D0|0]、L2B(g,1)=[0|D1] にする必要がある。
- L1BM→L2BM は L2B を指定できないので、0 埋めは PE の T 間接と l1bmm/l2bmd の倍増でしか作れない。
  - 18：T、l1bmm 2、l2bmd 2 で 8 語以上になる。
  - 27：l2bmd が 8 本になる。
- DAR が変えるのは DRAM の書き先だけで、L2BM の中身の違いは作れない。

### 39.matmul（MV 2）
- 出力は L2B ごとに別の行（K の部分和ではない）。mvr2 で 1 語にするには 0 埋めが要り、l1bmr が 16 本になる（既存 REPORT のとおり 29 のまま）。
- DAR の書き先の振り分けは、L2B の区別には効かない。

### challenge/19.inversion（MV 2）、challenge/20.fizzbuzz（MV 2）
- 19 は全 L2B の縮約と放送（mvr → PDM、mvb → L2BM）である。L2BM を書き先にできる縮約はないので、2 語が要る。
- 20 は 8 L2B の結合（mvd → PDM）とグループ 0 の DRAM への書き出しである。
  - 1 語で 8 L2B 分をグループ 0 の DRAM に書く命令はない。mvr と mvr4 は、グループ 0 には slot 0 しか書かない。
  - mvr2 と mvp は、グループ 0 の L2B だけで 4096 長語を作る必要があり、l2bmd が 64 本になる。

### challenge/16.count-up（MV 9）
- 出力はグループ 0 の DRAM だけなので、グループごとの DAR（48 で使った手）は使い道がない。
- DAR 間接の書き込みは 16 長語単位の並べ替えにしかならず、値を作らない。
  - 最後の結合（mvd）では L2B 番号がビット 4〜6 になる。L2BM の中身が全部同じだと、同じ塊が 8 回ずつ現れる。
  - 1024 個の互いに違う塊の並べ替えにはならないので、G0 との和（mvp と mvr2 の 2 語）は消せない。
- 新しい構成も検討した。4 グループがそれぞれの DAR で窓を複製し、mvr で 4 項を足して PDM から DRAM に出す、MV 4 語の案である。
  - nd16 でも 16384 長語に 64 エントリ/グループが要り、l2bmdarw だけで 16 行かかる。
  - ブロックごとに定数の項は窓の複製では作れない（重なる窓が同時に定数になれない）。
  - 20 語以下には届かない。
- 既存 REPORT の 7-MV 構成（a≥8 で 20 語と見積もり）を DAR で軽くする方法も見つからなかった。

26 と count-up の結論は分析と語数の数え上げによるもので、DAR の試作は作っていない（見積もりの費用が節約分を明らかに上回るため）。
