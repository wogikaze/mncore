# 25.hsv2rgb（HSV2RGB）短縮の記録

結論：12語（answer.vsm、公開 Top と同じ）から縮められなかった。
表引きで色を選ぶ設計では、12語が下限になると判断した（§4）。ハードウェア制約から組み立てた議論で、完全な証明ではない。
answer.vsm の判定（再確認済み）: `ACCEPTED!! score=12 j=12 m=0 bytes=759`

## 1. answer.vsm（12語）がしていること

`tr.py` で各行の値を確かめた（公式エミュレータで1語ごとに状態を出す）。
画素は PE あたり8個ある。H, S, V は `$lm0v6` `$lm2v6` `$lm4v6` に入っている。全 MAB に同じ入力が置かれている。

- **定数を1つの imm から作る**
  - L1 で `imm 0x43004300` を実行する。
  - `$alufe` で読むと、MN-Core の半精度（指数6ビット、bias 31）の 0x4300 が 6.0 になる。これで L2 が 6H を作る。
  - L2 の `filrelud $msb1` で 2W = 256.5 を作る。
  - L3 の `fvmulr` でその2乗を半精度に丸める。
  - L4 の `hvfma $mauf $lr0vr $aluf` で 2^23+0xC040+floor(6H) を作る（マジック数による整数化）。
- **表引き**
  - L4 で T に表 `0x10423880` を置く。
  - L5 の `iadd $mabid` でシフト量を s = i+m にする（m は MAB 番号）。
  - L6 の `ilsl` で T_m = 表 << s を作る。
  - 以後は relu0/2/3（bit31/29/28）のビット判定で係数を選ぶ。
- **MAB 間の分担**
  - MAB14 の T を L1BM 経由で MAB0 に送り、frelu2 に使う。MAB2 の 3値係数（frelu3 でマスクを作り、filrelud/$imr1 で選ぶ）も送り、R に使う。`l1bmd-11` で別の MAB の P7 を受け取り、G に使う。
  - B は「MAB4 で計算した G 型の式」を L11 で集め、L12 で書く。
- **値の組み立て**
  - t = V−SV+SVf を作る。
  - G = t − C8·f + P7（C8∈{0,SV,2SV}、P7∈{0,SV}）。
  - R = max(P9, t) − C8'·f（P9∈{V+SVf, −0}）。
  - LM1 への書き込みは G が L10、R が L11、B が L12。

## 2. 試したこと

1. **floor とマジック数を1回の FMA にまとめる**（鎖を1段縮める案）。
   - H から1回の fvfma で floor(6H) の整数ビットを得るには、加数が 2^23+0.5 のような値でなければならない。これは単精度で表せない。
   - 2^23 より少し下に置くと、H<1/24 の範囲で ulp が 0.5 になって壊れる。
   - x=6H を先に作り、y = X·Y + x とする方法はある。X·Y が丸め前に厳密に (n+0.5) になればよい。タイの丸め方向は ε を足して揃えられる。
   - しかし L3 で X·Y に使えるのは、L1 の imm W と、L2 の ALU 1命令でそれを変換した値だけである。しかも W は同時に 6 を出さなければならない（W=0x43004300 か ≈0x40C00000）。この条件で 2^23 前後の積は作れなかった（2倍、1/2、整数化、ビット演算、シフトを列挙した）。
2. **ftoi を使う**。
   - ftoi はゼロ方向に丸めるので、6H≥0 なら floor と同じになる。これで MAU のマジック数が要らなくなる。
   - ただし f には float の floor も要るので、ALU が1つ増える。
   - さらに表の imm を置ける行（LM0 に触らない行）が L1 しか残らず、6 の imm とぶつかる。
3. **新しい選び方**（成立したが語数は同じ）。
   - X = V − SV·[c]·f − [d]·u の形にする（u = SV−SVf、c と d は表のビット）。
   - 表 0x71C00000 を relu1/relu0/relu3/relu2 で読み、MAB0 で G と R、MAB4 で B を作る。
   - ilsl から G までが3段になり、答えの4段より短い。
   - しかし最後の行で R（MAU）と B（L1BM）が LM1 に同時に書くことになり、組めなかった。assembler が `out_lm1` の衝突として拒否することを確かめた。
4. **選択を共有して2チャネル目を1行早める**。
   - 各チャネルの「f を選ぶ条件」と「u を選ぶ条件」を、底が V/p/q/t の4形すべてについて調べた。
   - 2チャネルで条件の集合が一致する組は無い（R:{1,2,3}、G:{3,4,5}、B:{0,1,5} など、どの型でも3つとも違う）。
5. **3値選択を組み合わせて最終値を1命令で作る**。
   - filrelud とマスクで作れるのは {y, 2y} や {0, y, 2y} である。
   - {V, p, q, t} は平行四辺形の関係（V+p = q+t）を満たす。それでも定数項が無いので一致しない。
   - 積が階数1になる形では 0 が2つ出てしまい、4値を作れない。
6. **MAB0 だけで計算する**（mabid なし、ilsl を L5 に繰り上げ）。
   - チャネルあたり MAU が2つ以上要る。前処理の SV と f も合わせると、MAU の欄が足りない（L5〜L11 の7欄に8つ以上）。
7. **単純な |6H−a| とクランプ（min/max）の式**。
   - チャネルあたり ALU が3つ要り、表引きより多い。
8. **T 間接参照で LM0 から表を引く**。
   - 1長語の2要素が同じアドレスを使うので、画素ごとに違う番地を引けない。

## 3. 測った・確かめた規則

- imm と、LM0 に触る命令は同じ行に置けない（仕様。答えの行の割り当てもこれに従っている）。
- 1行で LM1 に書けるのは1回だけ（`out_lm1` の衝突として assembler が拒否する）。
- GRF の値は、書いた行の2行後から読める。
- `$alufe` の 32bit 語は、上位16ビットが要素0、下位16ビットが要素1になる。
- ftoi はゼロ方向に丸める。
- 同じ行で LM0 を読めるのは1か所だけ。そのため S·V を作るには、V を L1BM で折り返して渡す必要がある。

## 4. 下限の議論

- L1 は imm にするしかない（6 を作れるものが他に無い）。6H は L2 で作り、L3 から使える。
- MAB ごとにずらすには、鎖の中に iadd $mabid が1段要る。表の imm と float の floor にも ALU の欄が要る。このため ilsl は L6 より前に置けない（§2-1, 2-2）。MAB0 だけで計算すると MAU が足りない（§2-6）。
- 各チャネルの値は V, p, q, t の4通りなので、表による選択が2回要る。
  - ALU は1行に1つしか置けない。
  - T は L7 では aluf として、L8 からはレジスタとして読める。
  - 別の MAB の選択結果を使えるのは、計算した3行後からである。
- その結果、次のことが言える。
  - 最初のチャネルは L9 より前にできない。
  - 2つ目を L10 で作るには、選択か途中値を共有する必要がある。これは不可能だった（§2-4, 2-5）。
  - 別の MAB で作ったチャネルは、集める行と書く行が要るので L11 になる。
  - LM1 への書き込みは1行に1回なので、3チャネルを L9/L10/L11 に分けられない。
- 以上から12行が必要になる。
