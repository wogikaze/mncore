# 19.inversion 短縮の調査報告

結論: 31語（j=29, m=2）より短い ACCEPTED 解は見つからなかった。
いちばん近づいたのは 30語の候補 `c30c.vsm` で、数値の組み立ては通るが、公式アセンブラのハザード検査
（PE→L1BM ⇒ L1BM→L2BM の待ち）で落ちる。

## 1. answer.vsm の中身

- コピーの割り当て。
  入力は全グループ・全 L2B・全 L1B に同じものが置かれている（`d set` に n/c/b の指定がない）。
  解答は 64 個のコピー（l2bid 0..7 × l1bid 0..7）で比較を分担する。
  - 1行目 `ipackbit $l2bid $ls128 $mb` で BAR = 2·l2bid（要素オフセット p）。
  - 3行目 `ipackbit $l1bid $ls128 $t` で T = 2·l1bid（要素オフセット q）。
  - 各 long word はある PE の (行0[j], 行1[j]) で、2行を2レーンで同時に処理する。
- 比較の組。
  X_a = A[p+8a]（a=0..7）、W_b = A[p+q+8b]（b=-1..6）とおき、b<a の全組 36 個を比べる。
  1コピーあたり 36 比較 = isub 9行（5〜13行）で、64コピー合計は 2304 比較になる。
  W_{-1} が負番地になる場合は LM0 の上端（0）を読むので、結果は常に真になる。
  こうした比較は合計 288 個で、データに依存しない定数として相殺される。
  - S = X_4..X_7 は `spassa` で ls168.. に置く（4行目）。
  - R = X_0..X_3 は L1BM の折り返し（8行目で送り、9行目で `$ls160v`）で置く。
  - 8・9行目の y は `$lbf` から読む。8行目の LM0 読み出しは R の送り（`$lm0v16`）が占めているので、同じ値を L1BM 経由で遅らせて渡している。
- 計数の方法。
  `isub x y $omr` は x−y≥0（非転倒）でフラグを立てる。
  次の行の `fvadd acc -K acc/$imr` が、条件付きで K を引く。
  - 定数は imm 1つ（0x49800010 = 2^20+2）だけ。
    V² を丸めると 2^40+4単位（1単位 = 2^20 = 8ulp）になり、これを set1 の初期値にする。
    V²+V = 5単位を set0 の初期値にする。
  - set0 は 6,8,10,12,14 行、set1 は 7,9,11,13 行で更新する。
    GRF は書いてから 7 サイクル後でないと読めないので、2組を交互に使う。
  - 8個のアキュムレータの和は 2^43 台に入り、そこでは ulp がちょうど 1単位になる。
    最後の `fvadd/$imr3` が、4行目の `hvpassa -$mauf $omr3` で作った 0101 マスクで上位半語を 0 にする。
    これで下位 16 ビットにコピーごとの転倒数（≥0）が残る。
- 尾部（20〜31行）。
  l1bmd → nop×2 → l2bmriiadd（8 L1B の和）→ nop → mvriiadd（8 L2B の和）→ mvb → nop×2 → l2bmb → nop → l1bmd で LM1 へ書く。
  どの nop もハザードの待ちに必要である。

行数の内訳は、準備 4 行（ALU: mb, imm, T, spassa）、isub 9行、最後の減算 1行、和 5行（15〜19）、尾部 12行。

## 2. 試したこと

### A. 和を 4 行にする（候補 `c30a`〜`c30c`）
- cycle 3 で終わる 4 行の和の木は作れる。
  - 15行目 c0 = B0+B1、c1 = B2、c3 = B3+A0。
  - 16行目 c0 に +A1、c3 に +A3。
  - 17行目 c0 に +A2、c3 に +(15行目 c1)。
  - 18行目 c3 に +(17行目 c0)。
  この木には、set1 も ls に写しを持つことが必要になる。
- その写しは、9行目で R を `$ls160v` に書く命令と衝突する（GRF1 への書き込みは1行に1命令まで、`c30a` が落ちた）。
- そこで R を GRF に置かない比較の割り当てに作り直した（`c30c`）。
  - 9・12・13行目の x を LM0 から直接（BAR のみで）読む。
  - y は 2行前の S 行が読んだ W の並びを、L1BM の折り返しで `$lbf` として受け取る。
  - 36 組の割り当て、spassa の並べ方（GRF の読み出し待ちを避ける）まで含めて組み立てた。
- 結果: 最終値が cycle 3 にあると、`l1bmd $mauf $lb0` の cycle 3 の領域（lb192）を 3行後の l2bmriiadd が読めない。
  - cycle 0・1 なら通り、cycle 2・3 はハザードになる（アセンブラで確認）。
  - nop を1つ足すと元の 31 に戻る。
- 最終値を cycle 0・1 に置き、和の器が1つ（ALU だけ、または MAU だけ）で 4 行に収める木は、入力の数から不可能と分かった。
  - 15行目で読める A は A0 だけで、それも cycle 3 に限られる。
  - 各演算の入力は 2 つで、mauf は同じ cycle にしか流れない。
  - 数えると最大 7 項にしかならない。

### B. 準備を 1 行縮める（候補 `c30d`）
- S を spassa の代わりに L1BM の折り返しで置く案。
  - 2行目で送り、3行目で受けて `$ls168v` と `$lbf` に入れる。
  - imm は 3行目に移す（imm と LM0 アクセスは同じ行に置けない）。
  - 最初の isub を 4行目にする。
- 抽出用マスク 0101 は、空いた ALU で `ipassa $msb1` と `spassa` の2命令で作れる。
- 詰まった点: 2組のアキュムレータ（lr に2組、ls に set0 の写し）を、4行目の MAU 1命令で初期化しなければならない。
  - 1命令から同じ GRF0 へは2か所に書けない（"GRF0 used twice as output"）。
  - LM1 は書いてから 3 行後でないと読めない。
  - T は 5〜12行目のアドレス計算に使っている。
  - 定数を imm 1つで賄う制約とも両立しなかった。

### C. fvfma の丸めで比較と加算を一体にする（机上の検討のみ）
- 考え方。
  - x に整数オフセット K（例: 0x40400000）を足すと、isub の結果 D が有限の浮動小数点数になる。
  - `fvfma $aluf s acc` で丸め境界を d=-1/0 の間に置けば、マスクなしで acc が1単位増える。
  - 必要な s はたとえば 11184811·U·2^-26 で、浮動小数点数として表せることを確かめた。
- 長所: アキュムレータは mauf 鎖の4個で済み、交互の組が要らない。
- 短所: GRF 側の 8 値すべてにオフセットが要り、ALU のロードが1つ増える（isub の終わりが 14行目になる）。
  - s と初期値の定数も、imm を増やさずには作れない。
  - 4値の和は 3 行かかる。
  - 見積もりでは最良でも 30 で、定数の問題が未解決のため実装していない。

### D. その他
- 比較数の下限。
  2オフセット（p, q）方式では、e1 の列ごとに 8 の倍数ぶん覆う必要がある。
  そのため 1コピーあたり 35 比較以上になり、isub は 9 行のまま減らない。
- 4 比較/行を超える方法（半語で2値を詰めて比べる）は、詰める操作の ALU のコストが合わない。
- 1オフセット方式は 63 比較/コピーで、話にならない。
- 尾部の nop を計算で埋める案。
  尾部の時点で意味のある結果を持つのは c0b0 の 1コピーだけなので、1行あたり 4 比較の価値しかない。

## 3. 短縮を阻んでいるもの
- ALU: 準備 4 命令（BAR, T, 定数, x のロード）+ isub 9行が直列に並ぶ。isub の数は比較数 36/コピーの下限で決まる。
- MAU: マスク付き減算が 9 行連続し、和を先に取る空きがない。
  最後の減算から 1 値にまとめるまでの行数は、GRF の書き込みから読み出しまでの 7 サイクルと、最終値の cycle の制約（L2B 縮約が読めるのは cycle 0・1 だけ）で 5 行に縛られる。
- 尾部の 12 行（MV 2語を含む）は、ハザードの待ちとしてすべて必要。
