# DRAM 転送 15 問（17〜31）への手法 A・B の適用

手法 A: `ipassa $peid $t` で T を 1 命令で作る（2 長語読み出しの番地切り捨てを使う）。
手法 B: ハザードの待ちはサイクル単位で判定されるので、データを後のサイクルで読まれる番地に置いて nop を減らす。

## 測った規則（新しく分かったもの）
1. **L2BM→L1BM ⇒ L1BM→PE の待ち**（3.6.3.6）は、書き込みサイクルから読み出しサイクルまで 7 以上の差が要る。サイクル単位で判定される。
   - 直後の行で読む場合、条件は c'≥c+3 になる。満たせるのは「書き込みサイクル 0 のデータを読み出しサイクル 3 で読む」組み合わせだけである。
   - l2bmb の dst は 16 の倍数でなければならない。l1bmm の src は 8 の倍数でよい。
2. **L1BM→L2BM ⇒ MV の待ち**（3.6.3.1）は、サイクルでも行の距離でもなかった。プログラム先頭からの命令列の中身で決まる。
   - 直前の行の L1BM→L2BM が書いた番地を MV が読むとき、次の 2 条件をともに満たせば nop が要らない。
     - MV より前に nop 以外の PE 行が 4 行以下である。
     - nop が 1 行以上ある（nop の位置は問わない）。
   - nop 以外の PE 行が 5 行以上あると、nop を何行足しても racy になる（imm を詰め物にして 10×10 の表で確認した。nop だけの詰め物ではこの検出は起きない）。
   - 1 つ前の L1BM→L2BM の領域を読む場合は、常に問題ない。
   - 18（2 行）、25、29（4 行）は、この条件の範囲内なので nop が無い。20（6 行）と 27（7 行）は範囲外なので nop が要る。
   - パッカー（`--packer`）を付けると、アセンブラ自身がこの位置に nop を挿入する。
3. **2 長語の PE 側アクセスは 4 語にアラインが必要**で、Flat 指定でも同じである。l1bmd の L1BM 番地は 64 の倍数でなければならない。
4. **判定対象の PE が一部だけの問題がある。**
   - 19・21・22・28・30 は MAB0 だけ、19・28・30 は L1B0 だけ、30 は PE0 だけを見る。26 は L2B (0,0) と (1,1) だけを見る。
   - ただし PE が受け取れる量（2 長語/サイクル）と LM0 の書き込みポート（1 行に 1 つ）があるので、どの問題も縮まなかった。

## 問題ごとの結果

### 24.dram-dl-16（4→3、改善）
```
mvb/n64 $d0 $lc0
l2bmb $lc0 $lb32
l1bmm $llb8 $llm0
```
- 記録解は `mvb`、`l2bmb $lc0 $lb0`、`nop`、`l1bmm $llb0 $llm0v/ll1000` である。必要なデータは 8 長語で、l2bmb がサイクル 0 で書いた分だけである。
- 手法 B を使った。データを lb32 に置き（l2bmb のサイクル 0 で書かれる）、`l1bmm $llb8 $llm0` で読む。
  - lb32 を読むのは l1bmm のサイクル 3 になり、差は 4+3−0=7 で条件を満たす。
  - サイクル 0〜2 は lb8..31 を読む。ここは誰も書かない領域（ゼロ）なので、ハザードにならない。
  - PE 側は `v` なし（毎サイクル同じ番地）にした。最後のサイクル 3 の値が lm0..3 に残る。
- lb16 から読むと lb24 がサイクル 2 で読まれ、racy になる（`c3_bad16.vsm`）。
- j=2 は「L2BM→L1BM 1 行、L1BM→PE 1 行」の最小なので、これが下限である。

### 17.dram-dl-256-16（5）
- 残る待ちは l2bmd→l1bmm の nop 1 行（3.6.3.6）である。
- 各 PE は 8 長語が要る。PE 側は 2 長語/サイクルなので、l1bmm の 4 サイクルすべてが有効データを読む。
- 直後の行に置くと c'≥c+3 を満たせるのは 1 組だけになる（`c4_nonop.vsm` は racy）。
- l2bmd を 2 つの mvp の間に置いても、MV は PE のステップを消費しないので待ちは減らない。

### 18.dram-ul-256-16（6）
- 残る待ちは l1bmm@0→l2bmd の nop 2 行（3.6.3.7）である。
- 各 L1B 32 長語を、l2bmd が 8 長語/サイクルで 4 サイクルかけて読む。nop 1 行では c'≥c+3 になり、使えるのは 8 長語だけになる（`c5_onenop.vsm` は racy）。
- 書き込みをサイクル 0 にまとめても（l1bmm4/l1bmd）、読み出し側はサイクル 3 の 64 長語/L2B しか取れない。
- MV の nop は上の規則 2 によって元から無い。

### 19 / 21 / 22 / 28（19 / 12 / 8 / 7）
- 共通の待ちは、最初の L2BM→L1BM の次の行に l1bmm を置けないことである（規則 1）。
- l1bmm の本数は PE 側の受け取り量（2 長語/サイクル/PE）で決まり、それぞれ 16/8/4/4 本になる。
- 最初の行の l2bmb/l2bmd と最初の l1bmm の間の 1 行は、手法 B でも 1 サイクル分しか救えない。
- 判定対象が MAB0 だけでも、PE 当たりの量は変わらない。したがってすべて最小である。

### 23 / 26（68 / 39）
- l2bmd は 64 本と 32 本が帯域で決まっている。最後の l2bmd のデータを読む l1bmd は 2 行後になる。
- 手法 B で 1 行前に置けるのは、サイクル 0 で書いた 8 長語/L1B だけである。残りの 3 サイクル分は使わずに捨てられないので、短縮できない。
- 26 は MV 5 語である。mvb、mvd、mvb4 は 16 長語単位でグループを交互に並べる。このとき l2bmd の L1B l はグループ l>>1 のデータしか受け取れないので、使えない。

### 20.dram-ul-256-16p（10）
- 待ちは次の 3 つである。
  - T（imm+llsl）の後の 1 行。
  - W2 と重ねた PE→L1BM→L2BM の 1 行。
  - MV の前の 1 行。
- 手法 A: T=4·l1bid が要る。`$peid`/`$mabid` では代わりにならない。1 命令で作れるのは BAR+T（`ipackbit $l1bid $r0 $t $mb`）だけで、BAR は 2 行待つので語数は同じである。
- 手法 B: R1 は W1 の 4 サイクル分すべてを読むので、1 行前に出せない。
- MV の nop: nop 以外の PE 行が 6 行あるので、規則 2 により消せない（`c9_nomvwait.vsm` は racy）。T を 1 命令にしても 5 行で、まだ範囲外である。
- 入力は各グループの L2B0 にしか無い（testcase で確認）。そのため、2 つの L2B と 2 つの mvp に分ける案は使えない。

### 25.dram-ul-16（4）
- すでに手法 B を使っている（lb24 をサイクル 3 で読む）。
- 残る nop は PE→L1BM→L2BM の待ちである。直後の行では差が最大 7 で、必要な 11 に届かない（`c3_nonop.vsm`）。
- 1+1+1+MV が下限である。

### 27.dram-ul-16-1024（13）
- 前回の REPORT が下限とした構成で、手法 B も効かなかった。
- 4 本の l2bmd はすべてのサイクルで有効データ（計 1024 長語/L2B）を読む。最初の l2bmd を 1 行前に出すと、サイクル 0〜2 が 11 サイクルの条件を満たさない。
- 最後の nop は規則 2 によるもので、nop 以外の PE 行が 7 行ある。
- 手法 A: 1 長語読み出しで T∈{4x,4x+1} が要り、1 命令では作れない。

### 29.dram-ul-16-16（8）
- 記録解はすでに手法 B を使っている（lb32 を l2bm のサイクル 2・3 で読む）。
- nop を 1 行にするには、32 長語を 1 サイクルで読む必要がある。それには複数の L1B から読む命令（l2bmd/l2bmr2）が要り、T が l2bid と l1bid の両方に依存しなければならない。
- 2 命令以下で T=8·l2bid+4·l1bid を作る式を探した（`29.dram-ul-16-16/enum_t.py`、整数演算全種 × 固定値入力 × T/BAR+T）。解は 0 件だった。mvr4・mvr を使う別のレイアウトでも、必要な ID は 2 つ以上になる。
- T を使わない案も試した。mvr（全 L2B の縮約で、グループごとに 16 長語ずつ振り分ける）なら、L2BM の内容を全 L2B で同じにできる。flat 指定の l1bmm@0 4 本、l2bm@0 2 本、`mvrfmax/n128` の 7 語案である（`c7_flat_mvr.vsm`）。
  - 次の 2 点のハザードで不成立になり、修正すると 8 語以上に戻る。
    - l2bm@0 の 1 サイクルは 16 長語＝2 スロットを読む。そのため l1bmm@0 の後半サイクルの書き込みに引っかかる。
    - MV の前の非 nop 行が 6 行あり、規則 2 の範囲外になる。

### 30.dram-dl-256（10）
- 判定対象は各グループの PE0 だけである。2 長語の L1BM→PE 転送は (lb[a], lb[a+4]) の組でしか届かない。
- LM0 の書き込みポートは 1 行に 1 つで、2 長語の書き込みは 4 語アラインが要る。この 2 つの制約から、組を並べ替える後処理（$lbf のフォワーディングと frelu）が必要になる。
- 最初の l1bmp を L2 に出しても、手法 B で有効になるのはサイクル 3 だけである。今の L3〜L6 の転送 16 サイクルは全部必要なので、縮まない。
- 後処理の行を減らす案（マスクを使った GRF 上での組み立て）は未完了である。記録解は人が詰めた 9 PE 行の解である。

### 31.dram-ul-256（7）
- 残る待ちは次の 2 つである。
  - T（ipackbit で T=2·peid）の後の 1 行。
  - l1bmd→l2bm@0 の nop 2 行。
- nop を 1 行にすると、l2bm のサイクル 3（16 長語）しか使えない（`c6_onenop.vsm` は racy）。
- 32 長語を 1 サイクルで読むには複数の L1B が要り、T は peid と l1bid の 2 つの ID に依存する。1 命令では作れない。
- 入力は全 PE で同じなので、T なしでは PE ごとに違うデータを書けない（j 修飾と mabdiff も試したが不可）。
