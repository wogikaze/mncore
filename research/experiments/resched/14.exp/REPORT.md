# 14.exp（Exp）短縮の記録

結論：16語から14語に縮めた（`exp14.vsm`、`ACCEPTED!! score=14 j=14 m=0 bytes=633`）。
13語は、使える定数の数と依存の鎖の長さの両方で行き止まりになると判断した（§4）。

## 1. 記録済み answer.vsm（16語）がしていること

`trace.py`（公式エミュレータで1語ごとに状態を表示する）で各行を確かめた。
オペランドの並びは「入力…、出力」である（`hvadd $t $llm0v $lls0v` は T+LM0 を GRF1 に書く）。

- 入力は全 MAB に同じものが置かれ、出力は MAB0 の LM1 だけが読まれる。
  fv 命令は PE あたり1命令で8個しか処理できない。
  そこで MAB0 が偶数番目の長語（x[0,1,4,5,…]）を、MAB4 が奇数番目を受け持ち、最後に L1BM 経由で MAB4 の結果を MAB0 の `$ln2v4` に運ぶ。
  - 1行目：`ipassa $mabid $omr1`（MAB0 だけフラグ1）と、x を GRF1 にコピー。
  - 2行目：`fvpassa $mauf $ls2v4/$imr1` で MAB0 の `$ls2v4` だけを偶数側に書き換える。
- 計算は e^x = 2^k·(e^{r/2})²。k = floor(x·log2e + 0.5)（ffloor）、r = x − k·ln2。
  e^{r/2} は5次 Horner（係数 1, 1/2, 1/8, 1/48, 1/384, 1/3840）で求め、fvmul で2乗する。
  最後に ilsl（k≪23）と iadd で指数部に k を足す。
- 定数は imm 6個。残りは L1BM の縮約で作っている。
  - 0.125 を4MAB縮約すると 0.5 になる。
  - −1/384 を fvadd で2倍して4MAB縮約すると −1/48 になる。
  - −1/48 を16MAB縮約し、さらに半精度の4MAB縮約にかけると −85.34 になり、fmax の閾値に使う。
  - ln2 の imm は 0x3F317217 で、下位ビット 0x17=23 を ilsl のシフト量に兼用している。
    ln2 との誤差（k·5.8e-8）は、c0=0.99999994 でほぼ打ち消している。
- 閾値の fmax で作ったマスクで、k が −128 以下になる入力を 0 にする。
- 鎖：t(5) → floor(6) → r(7) → Horner(8–12) → 2乗(13) → iadd(14) → L1BM(15) → 書き込み(16)。

## 2. 14語版 exp14.vsm

```
ipassa $mabid $omr1; hvadd $t $llm0v $lls0v
imm ui"0x4B400080" $llr32v; fvpassa $mauf $ls2v4/$imr1
imm ui"0x3FB8AA3B" $nowrite
imm ui"0x3F317218" $lr40v; fvfma $ls2v4 $aluf $lr32v $ls48v
imm ui"0x3B87ABA6" $lr48/1000; fvadd $mauf -$lr32v $nowrite
imm ui"0x3CABAD17" $ln20; fvfma $mauf -$lr40v $ls2v4 $t
imm ui"0x3DAAAC79" $nowrite; fvfma $mauf $lr48 $aluf $nowrite
imm ui"0x3E7FFE8D" $nowrite; fvfma $mauf $t $aluf $nowrite
imm ui"0x3F000001" $lr52/1000; fvfma $mauf $t $aluf $nowrite
ilsl $ls48v $ln20 $lr60v; fvfma $mauf $t $aluf $nowrite
fvfma $mauf $t $lr52 $nowrite
fvmul $mauf $lr60v $ln0v4
l1bmm@2 $mauf $lbi
l1bmm $lbi $ln2v4
```

元の解から次の3点を変えた。

1. **丸めをマジック数にした**（ffloor・fftoi・fmax・閾値が不要になる）。
   - t = x·log2e + M（M = 1.5·2^23 + 128）とすると、t の下位ビットが k+128 になる。kf = t − M は厳密に k。
   - `ilsl t, 23` は M の上位ビットを捨て、S = (k+128)≪23 = 2^{k+1} という float をそのまま作る。
   - k = −128 では S のビットが 0（= 0.0）になり、k = −127 では積がアンダーフローして 0 になる。マスクは要らない。
   - 係数を 1/2 倍し（e^r/2 を近似）、最後に fvmul(p, S) で掛ける。
2. **2乗をやめて、e^r を r の5次で直接近似した**。
   - 鎖は t → kf → r → H1..H5 → fvmul の9段になる（元は ALU を含めて10段）。
   - 0.5 を L1BM で作る待ちがなくなり、最初の演算が w4 から始まる（元は w5）。
3. **定数の置き方**。
   - シフト量 23 を c4 の下位6ビットに埋め込んだ（lsl は s mod 64 を使う）。c4 は aluf として H1 に入り、同時に LM1 に置いて ilsl が読む。
   - c0 と c1（半分にした値はどちらも ≈0.5）を同じ値に縛った。1回の imm を aluf と GRF0 に兼用して、ALU 欄を1つ空けた（そこに ilsl が入る）。
   - 同じ行で同じファイルに2回書かないように、GRF0・GRF1・LM1・T を振り分けた。/1000 マスクと「v で書いて v で読む」形で、ハザードの nop を出さないようにした。

## 3. 精度について

- 問題の許容誤差は絶対誤差 1e-6。
- 期待値は丸める前の x（倍精度）から作られているらしく、exp(float32 の x) と最大 8.4e-7 ずれる。
  そのため [4,8) では 2ulp（9.54e-7）までしか許されない。answer.vsm も最大誤差 9.54e-7 で、ちょうど境界にいる。
- 連続 minimax の誤差は、5次で 3.8e-7、c0=c1 に縛ると 4.8e-7 になる。
  その係数そのままの `a14.vsm` は、テストケース中の1点が 1.43e-6 になって不合格だった。
- `fit/lp2.py` で係数を選び直した。
  テストケースの点と密な格子点の両方に LP をかけ、float32 の格子上で局所探索した。
  `fit/opt.py` のシミュレータは、公式エミュレータの出力とビット一致を確認してある。
- 採用した係数での結果：
  - テストケースの最大誤差：9.54e-7（answer と同じ）。
  - x ∈ [−14, 2] の密な格子で exp(x32) と比べた最大誤差：9.5e-7。
  - テストケースだけに合わせた係数は密な格子で 1.5e-6 になったので、採用しなかった。

## 4. 13語を目指して試したこと・行き止まりの理由

14語の内訳は、前置き3行、鎖9段、末尾2行（L1BM への転送と書き込み）である。

- **最初の演算を w3 に繰り上げる（T 間接参照 `$lmt0v4`）**。
  - w1 の ALU は ipassa で埋まる。w3 は LM0 を読むので imm を置けない。w3 で使える定数は w2 の imm 1個しかない。
  - t = x·log2e + M は定数が2個要るので置けない。
  - u 形式（y = x·log2e → ffloor → u = x·log2e − kf、2^u を近似）にすると ln2 は要らない。
    しかし w6 の H1 に要る c5・c4 を用意できない。ALU 欄は w1=ipassa、w2=log2e、w3=imm 不可、w4=ffloor で埋まっている。
    L1BM でも log2e を4倍・16倍・半精度縮約した値しか作れない。
    さらに fftoi・ilsl・バイアスまたはマスクが要り、ALU 欄が2つ以上足りない。
  - log2e のビットから ALU 1命令で M を作る案も、y と t が別の段になるので r は w6 のまま。
- **鎖を短くする**。
  - t→kf→r を2段にはできない。r を t から直接作ると x + M·ln2 が float32 で表せない。倍精度（dv＋e）は処理量が半分になる。
  - 4次の minimax 誤差は 1.4e-5 で足りない。r/2 の4次＋2乗も誤差 1.3e-6 で、段数も同じ。
  - k を半整数刻みにすると 2^{k/2} の √2 因子が作れない。
  - スケールを Horner に畳み込むには要素ごとの c_i·S が要り、MAU 欄が足りない。
- **末尾2行を1行にする**。
  - L1BM の整数加算縮約（l1bmr4iiadd）で、奇数側の k≪23 の加算を転送のついでに行う案を考えた。
    縮約の入力は全 MAB で同じオペランド（$mauf）なので、MAB0 の偶数側の p が和に混ざる。
    4x4 放送は MAB0 にグループ0の和しか届けず、16x1 の和では MAB0 自身の分を 0 にできない。
  - 2長語の縮約は入力をメモリに置く必要があり、書いてから読めるまで1段空くので縮まない。
- **x の振り分けを省く**：hv 命令（4並列）は積が半精度なので使えない。

以上から、この組み立てでは 14 が下限に近いと判断した。
13 にするには、w3 で定数を2つ使える仕組みか、t→kf→r を2段にする仕組みが要る。どちらも見つからなかった。
