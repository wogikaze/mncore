# 16.count-up（Count Up）短縮の調査

結論：21 語（j=12, m=9）より短い解は見つからなかった。記録解（`base.vsm` にコピー）は `ACCEPTED!! score=21 j=12 m=9 bytes=830`。
MV を 7 語に減らす構成は作れた（`v1.vsm`、`ACCEPTED!! score=35 j=28 m=7 bytes=694`。PE 側は検証用に手早く書いたもの）が、
その代わりに PE に $l2bid の項が要る。記録解の ALU 欄は 1〜7 行目がすべて埋まっていて、この項を入れると 1 行以上延びる。
そのため、MV で減らした 2 語がそのまま打ち消される。

## 1. 記録解の動作（実測）
- 求める出力：長語 k に (2k+1 | 2k+2) を置き、全部で 16384 長語。値は k について線形なので、「周期部分 + ブロック部分」の和に分けられる。
- PE（12 行）は L2BM に 4 つの領域を作る。値は `d getd` の段階ダンプで確かめた。
  - lc128..255：(2k+1 | 2k+1)、k<128（A 部分）。`ipackbit $peid $mauf` で 2peid+1 を作る（mauf = −T なので MSB が 1）。これを L1B1 から `l2bm@1` で 2 回運ぶ。2 回目の値は `iadd $t $lr0`（lr0 = 128·l1b）。
  - lc256..511：16 長語ごとのブロックで値は 256·b（B2）。`l1bmr4fmin` を折り返し→`l1bmm4 $lbi`→`$lbf` と通して 1024·(mab>>2) を作り（mab&3 を消すマスク）、`l2bmr2fmin` で L1B の組の最小を取る。
  - lc768..：(2048h | 2048h+1)（B1）。値は L2B に依存しない。lo 側の +1 は、$s1 への半語マスク書き込み（`/$imr1`）と `ibsl` の回り込みで作る。
  - lc1024：8|8。`l1bmr4ior`（論理 OR なので結果は定数 1）と `l2bmriiadd`（8 L1B の和）で作り、DAR の元データにする。DAR には `l2bmdars` と `l2bmdarw`×4 で 16 エントリを書く。
- MV（9 語）の流れ：
  1. B1 を PDM に結合（mvd）。
  2. A と B2 を DRAM に置く（mvp）。
  3. DAR 間接読み（nd8）で、lc(0,0)[0:2048] に B2 の繰り返し、[2048:18432] に A の周期 128 を作る。
  4. mvp で PDM の B1 を lc(0,1)[0:2048] に置き、mvr2iiadd で B1+B2 を PDM に作る。
  5. 全 L2BM に放送（mvb）し、×8 結合（mvd）して PDM に 16384 長語を作る。
  6. mvp で lc(0,1) に置き、最後の mvr2iiadd で A と足して DRAM に書く。

## 2. 新しい 7-MV 構成（成立を確認）
- 出力の添字を p = 1024h + 128s' + 16u + t に分け、出力を G0 + G1 と書く。
  - G0：周期 128 の部分。DRAM_0[0:128] を DAR=0（初期値）の間接読みで繰り返す。DAR を書く命令は要らない。
  - G1：Q_{s'}[16h+t] を 2 段で広げたもの。結合（mvd）→ mvb → 結合（mvd）で作る。
- MV の列：
  ```
  mvp/n128 $lcR@0.0 $d0@0
  mvp/n16384nd8 $di0@0 $lcX@0.0
  mvd/n256 $lcQ $p0@0
  mvb/n2048 $p0@0 $lcY
  mvd/n2048 $lcY $p0@0
  mvp/n16384 $p0@0 $lcX@0.1
  mvr2iiadd/n16384 $lcX $d0
  ```
- PE が用意するもの：
  - Q_s：全 L2BM に 256 長語。値は 2048h+256s（語単位、t 方向の補正 φ(t) を足してもよい）。
  - R：L2BM(0,0) に 128 長語。値は 2r+(1|2)−φ(t)。
- 確認したこと：
  - `d set` で L2BM の中身を直接置いた試作 `proto_mv.vsm` は、DRAM が 16384 長語すべて正解だった。
  - PE を素直に書いた `v1.vsm` は公式 judge で ACCEPTED（score 35）。

## 3. 実測したハザード・仕様
- MV の行は PE の時間を進めない。最後の l2bm と、それを読む MV の間には PE の行が 1 行要る。間に別の MV を挟んでも、アセンブラは racy read で拒否する（`v2.vsm`）。
- 総語数の下限は「Q の値が確定する行 a」で決まる。内訳は l1bmd 1 行、待ち 2 行、l2bm 1 行、nop 1 行、MV 7 語で、合計 a+12 語になる。
- GRF は、書いた番地を 2 行後に読むと racy read になる。
- `l1bmd $lbf $lb0` と `iadd $lbf …` はアセンブラが受け付ける。
- `d get $p` は DRAM を表示する（NUMERICS.md に記載あり）。

## 4. 試した案と結果
- 記録解の PE をそのまま使い、MV を 7 語にする案：lc768（B1）に 256·s を足す必要がある。ALU 欄は 1〜7 行目がすべて使われている（imm、mab のシフト、l1b のシフト、packbit、Q 用の加算、R 用の加算、×8 の bsl）。s の項は ALU 命令でしか入らない（$l2bid は ALU の第 1 入力にしか置けない）。足すと、シフトと加算で 1〜2 行延びて 20〜21 語になる。$l2bid を他の命令に混ぜる方法は、どれもスケールが合わなかった。
- 6-MV 構成（Z6）：L2BM(g,0) の 640 長語を mvp で全グループの DRAM に置き、mvb（DRAM→L2BM、グループ連結）を使う。PE は 3 回の l2bmd が必要になる。さらに φ による補正で R が非線形になり、ALU 命令が増える。
- Q と R を同じ値から作る案：Q の l1b の係数は 1024、R は 128 で、スケールが合わない。u と h の係数でも矛盾する。
- φ で Q を線形にする案（例：レーン値 = 256(4(peid+l1b)+s)）：R の t 依存が非線形になり、マスク命令が要る。φ=0 にすると、今度は Q に peid>>4 のマスクが要る。どちらを選んでも 1 命令は残る。
- 浮動小数点で計算する案（1.5·2^23 のマジック数で整数を仮数に入れ、MAU の fma で和を取る）：ID 1 つにつき ALU 命令が 1 つ要る点は変わらない。さらに定数（2^k の倍率と相殺用の定数）が増える。ゼロに近い小さな整数のビット列は非正規化数として 0 に落ちるので、MAU で整数のまま扱うこともできない。
- 縮約による無料のスケール（l1bmr4iiadd で ×4、l2bmr2iiadd で ×2 と ×4）：3 つの ID（mab, l1b, s）を 32:4:1 の比に分けられない。縮約の倍率はすべての項に同じだけ掛かるからである。
- 周期を 64 や 32 に縮める案：2 段目の結合で放送されるデータは全 L2BM で同じなので、ビット 4〜6 は G0 が受け持つしかない。周期は 128 以上が必要になる。
- DAR 間接読みで値を増やす案：間接読みは窓をコピーするだけで、新しい値は作れない。ブロックごとに定数の値を並べるには、元データかエントリ数が足りない。

## 5. 下限の考え方
- 7-MV 構成では、Q が s, l1b, mab>>2 の 3 つの ID に、比 32:4:1（mab>>2 : l1b : s）で依存する。R は peid と l1b に依存する。
- ID は ALU の第 1 入力でしか読めない。命令ごとに足せる ID は倍率 1（iadd）か 2^k（シフト）なので、Q だけで ALU 命令が約 5 つ、R で約 2 つ要る。これに imm を加えると 8 命令以上になる。
- そのため a ≥ 8 となり、総語数は 20 語以上と見込まれる。ただしこれは手で数えた見積もりで、証明はしていない。
- 記録解の構成では、PE 12 行と MV 9 語で ALU 欄が飽和している。s の項を足す 1 命令を入れる余地がない。
- どちらの構成でも、21 語より短くするには上の見積もりを外す新しい手が必要になる。

## ファイル
- `base.vsm`：記録解のコピー。`dbg.vsm` はそのダンプ用。
- `emu.sh`：公式アセンブラとエミュレータを `d get`/`d set` 付きで実行する。
- `dump.py`, `stepdump.py`：途中の行で状態をダンプする。
- `check.py`：DRAM 16384 長語の正誤を判定する。
- `asmok.sh`：アセンブラが受け付けるかを調べる。
- `proto_mv.vsm`：7-MV の流れを `d set` で試したもの（正解）。
- `v1.vsm`：7-MV の素朴な全体解（ACCEPTED, score 35）。
- `v2.vsm`：MV の行が PE の待ちにならないことを示した失敗例。
