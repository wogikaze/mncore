## 22.bit-reverse: 10 → 9（`22.bit-reverse/c9a.vsm`）
### 記録解の仕組み
- MAB m が各16ビット語を m だけ回転し、$msb1 で bit15 を残し、m+1 だけ回転する。m+1 は `l1bmd-1` の折り返しで作る。
- これで bit(15-m) が bit m に移る。16 MAB 分を `l1bmrsbor` の OR 縮約で集めると、各 short が反転する。
- その後 short 順の反転に2命令かかる。swap16（imm 0x3E10 の下位ビット）と swap32（`hvmulr` で作ったシフト量）である。
- 最後に PE を逆順にし（msr / msl を PE の奇偶マスクで使い分け）、番地を逆順に書く（$ln[6,4,2,0]）。
### 短縮
- 1回目の回転を 16 ビット、2回目を 32 ビット（ibsl）にすると、32 ビット語単位の反転になる。残る並べ替えは swap32（lbsl 32）だけで、imm 32 を次の行の $aluf として読む。
- Python で網羅した。対象は「定数1命令 V(m)＋折り返しで MAB をずらした V(m+d)、回転精度・向き、$msb1 の精度、最後の並べ替え」の全組合せ。
- 解は `sinc $mabid`（V=m+1）、sbsl、sand $msb1、ibsl $lbf（d=1）、最後 swap32 などの4通りだった。`spassa`（V=m）では解がない。2回目の回転量が m+1 ∈ 1..16 になり、mod 16 の折り返しでは 16 を作れないため。
### 9 より縮まない理由
- 鎖: 定数（$mabid は第1オペランドにしか置けないので ALU 1命令）→ 回転 → マスク → 回転（折り返し）→ OR 縮約 → 折り返し放送 → swap32 → msr → msl ＝ 9段。
- swap32 を消す（最後まで 64 ビットで済ませる）組合せを探した。範囲は search2/3/4 で、V を任意の値・$mabid/$peid の単項演算・レーン非一様まで広げた。解は 0 件。
  - 理由は回転量の関係 r2 ≡ r1+1 にある。折り返しのずらし d で一周すると総和が 16 になり、mod 32/64 で 0 にならない。
  - 符号を逆にした組合せ（d=8）は、回転量の範囲 0..15 と両立しない。
- L1BM 転送はすべて PE 番号を保つ（分配・放送・縮約・4x4）。行列レジスタの転置1回でも PE の逆順は作れない。よって PE 逆順には ALU の msr/msl が2命令要る。
- ALU 命令数でも 8 行は無理。定数・回転・マスク・回転・swap・msr・msl・PE マスク・imm(32) ＝ 9。

## 13.mod3: 8（変化なし）
### 記録解の仕組み
- C=0x452ad551 を使い、2長語 smax で int を浮動小数に直す。上位 short に 0x452a を入れ、下位 short は負なので max で x が残る。MSB 長語は a=2720+x/4096 になり、LSB 長語は素通しの x のままになる。
- LSB 長語は L1BM 折り返しで直す。半語マスク（hvpassa の符号フラグ）付きで C の上位半語だけを書く。
- fvfma(a, C, −a) の丸めで、結果の仮数の下位2ビットが x mod 3 になる。それを `iand $t`（T=3）で取り出す。
- ALU 8命令: imm×2、smax×2、iand×4。--dirty でも ACCEPTED。
### 7 行にできない理由
- 出力は LM1 に整数 16 長語。MAU は非正規化数を 0 にするので小さな整数を書けない。L1BM の縮約は MAB 間で値が混ざる。よって ALU 1長語命令が4個要る。
- 鎖: imm → 変換 → MAU → iand で、最初の iand は早くて L4。ALU 7個にするには変換1個か imm1個を消す必要がある。
- 変換1個の場合: 2つ目の塊の変換を L1BM マスク書き込みで LM0 にその場で行うと、LM0 は書き込みの後2行読めない。L5 の iand に入力がない。
- T=3 を消して C をマスクに兼ねる場合: mauf の指数ビットと C の指数ビットが重なる。fvmul では指数が成り立つのは E∈{0x40..0x55, 0x7f} だけで、そのとき傾き 4/3 から C の仮数上位が 0x2A.. に決まり、mauf の仮数と重なる。fvfma(a,C,±a/±C) では指数で失敗する。
- 3 を L1BM 縮約（16C, 4C, 論理和=1）や L2 の MAU から作る案も成り立たない。

## 24.log2: 7（dirty 対応版 `24.log2/d7.vsm`）
### 記録解の仕組み
- T=0x0B808017 を、変換定数・減算定数・シフト量 23 の3役に使う。
- sadd で上位半語 0x0B80 を足す。fvadd −T で x·2^-127 にする（x=1 は 0 に落ちる）。ilsr 23 で指数部 = log2 x になる。
### dirty で落ちる原因と修正
- 記録解は `$ls32` を、未初期化領域への半語マスク書き込みで 0x0B800000 にしていた。--dirty では 512 個不一致になる。
- 修正:
  - 塊 A を GRF0、塊 B を GRF1 に置く。L2 の MAU が −S を ls32 に書く。
  - L3 で $mauf（−S）を折り返しに集める。
  - L4 の分配で B の LSB を −S の上位半語で直し、同時に −S を `$lr32v` へマスクなしで書く。
  - L6 は `fvadd −$ls18v4 $lr32v` で計算する（$lr32 単独読みは racy 判定になるので v にした）。
### 6 行にできない理由
- 出力 ALU 4命令に加え、鎖 imm(L1) → 変換(L2) → MAU(L3) → 出力(L4) があるので最短 7 行。
- 定数なしの変換（$msb1 との or、not、回転など）では正規化数を作れない。2つ目の塊の ALU なし変換は、mod3 と同じ時刻の理由で間に合わない。

## 7.mul2: 9（dirty 対応版 `7.mul2/d9.vsm`）
### 記録解の仕組み
- hpassa（2長語コピー）を、同じ LM0 領域を読む hvaddr r と同じ行に置く。
- `hilrelud $msb1` で 2Y を作る。2長語 ALU 命令の LSB 素通しで、前もって計算した 2X を流し、8長語ずつ書く（L7〜L9）。
### dirty で落ちる原因と修正
- L7 の `hrelu $lls48v` の MSB 側（ls48,52,..）を一度も書いていなかった（0 を仮定）。
- 修正: L3 に `l1bmrsor $mauf $lbi`、L4 に `l1bmm $lbi $ls48v4` を加えた。論理和の縮約で 0/1（符号 0）を書く。L1BM の空き欄だけで 9 語のまま。
### 8 行にできない理由（数え上げ）
- 前提1: 同じ行の LM0 読み出しは全員同じオペランド形でなければならない。アセンブラで確かめた。1長語 v4 と 2長語、番地違いはどちらも衝突になる。
- 前提2: MAU の hv 演算は1命令4長語。2長語読みでも MSB 側だけを計算する。
- 前提3: LM1 書き込みは1行1命令。8長語書けるのは2長語 ALU だけ。
- 8 行の場合:
  - LM0 読み出し 8C+4(8−C) ≥ 48 と LM1 書き込み 4C+8(8−C) ≥ 48 から、コピー行は C=4 に決まり、すべて等号になる。
  - 計算量も MAU 32＋ALU 16 = 48 で等号になる。
  - 最終行の MAU を生かすには最終行がコピー行でなければならないが、そこでコピーした値は誰も使えない。よって等号が崩れ、矛盾する。
